第 17 章 · Part 5：Adapters

自製 Custom Adapter

為任意網站打造專屬適配器，讓 OpenCLI 的能力無限延伸。

為什麼需要 Custom Adapter？

OpenCLI 雖然內建 80+ 平台適配器，但你的工作中難免會遇到需要自動化的內部系統、小眾平台，或是有特殊需求的網站。 Custom Adapter 讓你能用統一的 OpenCLI 介面封裝任意網站的操作，讓 AI Agent 能無縫使用。

四種開發方式

方式 A：Browser Init

在已開啟的瀏覽器 Session 中直接定義 Adapter，最快速，適合快速原型。

方式 B：Plugin Create

使用 YAML 宣告式格式建立 Plugin 檔案，適合大多數靜態網站。

方式 C：External Register

從外部 npm 套件或本地目錄載入 Adapter，適合跨專案共用。

方式 D：AI Skill

使用 opencli-adapter-author Skill，讓 AI 自動生成 Adapter 程式碼。

方式 B：YAML 宣告式格式

YAML 格式是最常用的 Adapter 開發方式，語法簡單直觀，適合大多數場景。

基本結構

adapter.yaml 基本結構 
name: my-site          # Adapter 名稱（用於 CLI 呼叫）
version: "1.0.0"
description: "My custom site adapter"
baseUrl: "https://example.com"

# 認證策略
auth:
  strategy: cookie     # public / local / cookie / intercept / ui
  cookieDomain: ".example.com"

# 指令定義
commands:
  - name: search
    description: "搜尋文章"
    args:
      - name: query
        type: string
        required: true
    steps:
      - navigate: "${baseUrl}/search?q=${args.query}"
      - wait:
          selector: ".results"
      - extract:
          selector: ".result-item"
          fields:
            - title: "h3"
            - url: "a[href]"
            - summary: ".description"

五種認證策略

策略 適用場景 說明
public 公開內容 無需認證，直接存取公開頁面
local 內部系統 本地網路或 VPN 環境，無需帳號
cookie 一般登入網站 使用瀏覽器現有登入 Cookie
intercept API 型網站 攔截 XHR/Fetch 請求，直接呼叫 API
ui 需要互動登入 模擬使用者操作完成登入流程

Pipeline Steps 完整參考

所有可用的 Pipeline Steps 
steps:
  # 導航到頁面
  - navigate: "https://example.com/page"

  # 等待選擇器出現
  - wait:
      selector: ".content"
      timeout: 5000

  # 等待文字出現
  - wait:
      text: "載入完成"

  # 擷取資料
  - extract:
      selector: ".item"
      fields:
        - name: "h3.title"
        - price: ".price"
        - link: "a[href]"

  # 執行 JavaScript
  - evaluate: "document.querySelector('.btn').click()"

  # 對列表進行 map 操作
  - map:
      source: "${{results}}"
      template: "${{item.title}} - ${{item.price}}"

  # 過濾結果
  - filter:
      source: "${{results}}"
      condition: "item.price > 100"

  # 排序
  - sort:
      source: "${{results}}"
      by: "price"
      order: "asc"

  # 限制數量
  - limit:
      source: "${{results}}"
      count: 10

方式 C：TypeScript 完整實作

對於複雜邏輯或需要精細控制的場景，TypeScript 提供更強大的能力：

my-adapter/index.ts 
import { defineAdapter } from '@opencli/adapter-sdk'

export default defineAdapter({
  name: 'my-site',
  version: '1.0.0',
  description: 'My custom site adapter',
  baseUrl: 'https://example.com',

  auth: {
    strategy: 'cookie',
    validate: async (browser) => {
      const cookies = await browser.getCookies()
      return cookies.some(c => c.name === 'session_token')
    }
  },

  commands: {
    search: {
      description: '搜尋內容',
      args: {
        query: { type: 'string', required: true },
        limit: { type: 'number', default: 10 }
      },
      async execute({ args, browser }) {
        await browser.navigate('https://example.com/search?q=' + encodeURIComponent(args.query))
        await browser.waitForSelector('.results')
        const results = await browser.extract({
          selector: '.result-item',
          fields: { title: 'h3', url: 'a[href]', summary: '.desc' }
        })
        return results.slice(0, args.limit)
      }
    },

    detail: {
      description: '取得詳細資訊',
      args: {
        id: { type: 'string', required: true }
      },
      async execute({ args, browser }) {
        await browser.navigate('https://example.com/item/' + args.id)
        await browser.waitForSelector('.item-detail')
        return browser.extract({
          selector: '.item-detail',
          fields: { title: 'h1', content: '.content', author: '.author', date: 'time[datetime]' }
        })
      }
    }
  }
})

五種標準指令模式

大多數平台的操作都可以歸納為這五種模式：

1. List（列表）

List 模式 
- name: list
  description: "取得列表資料"
  args:
    - name: limit
      type: number
      default: 20
  steps:
    - navigate: "${baseUrl}/items"
    - wait:
        selector: ".item-list"
    - extract:
        selector: ".item"
        fields:
          - title: "h3"
          - id: "[data-id]"

2. Search（搜尋）

Search 模式 
- name: search
  description: "搜尋內容"
  args:
    - name: query
      type: string
      required: true
  steps:
    - navigate: "${baseUrl}/search?q=${args.query}"
    - wait:
        selector: ".search-results"
    - extract:
        selector: ".result"
        fields:
          - title: "h3"
          - url: "a[href]"
          - snippet: ".snippet"

3. Get（取得單筆）

Get 模式 
- name: get
  description: "取得詳細資訊"
  args:
    - name: id
      type: string
      required: true
  steps:
    - navigate: "${baseUrl}/item/${args.id}"
    - wait:
        selector: ".detail"
    - extract:
        selector: ".detail"
        fields:
          - title: "h1"
          - body: ".content"
          - date: "time"

4. Action（操作）

Action 模式 
- name: like
  description: "按讚"
  args:
    - name: id
      type: string
      required: true
  steps:
    - navigate: "${baseUrl}/item/${args.id}"
    - wait:
        selector: ".like-btn"
    - evaluate: "document.querySelector('.like-btn').click()"
    - wait:
        selector: ".like-btn.active"

5. Monitor（監控）

Monitor 模式 
- name: monitor
  description: "監控頁面變化"
  args:
    - name: url
      type: string
      required: true
    - name: selector
      type: string
      required: true
    - name: interval
      type: number
      default: 30000
  steps:
    - navigate: "${args.url}"
    - wait:
        selector: "${args.selector}"
    - fetch:
        selector: "${args.selector}"
        field: "textContent"

實戰案例：Hacker News Adapter

讓我們建立一個完整的 Hacker News Adapter 作為實戰練習：

hackernews/adapter.yaml 
name: hn
version: "1.0.0"
description: "Hacker News adapter for OpenCLI"
baseUrl: "https://news.ycombinator.com"

auth:
  strategy: public

commands:
  - name: top
    description: "取得 Hacker News 頭條"
    args:
      - name: limit
        type: number
        default: 30
    steps:
      - navigate: "${baseUrl}"
      - wait:
          selector: ".athing"
      - extract:
          selector: ".athing"
          fields:
            - rank: ".rank"
            - title: ".titleline a"
            - url: ".titleline a[href]"
            - points: ".score"
            - comments: ".subline a:last-child"
      - limit:
          source: "${{results}}"
          count: "${{args.limit}}"

  - name: new
    description: "取得最新文章"
    steps:
      - navigate: "${baseUrl}/newest"
      - wait:
          selector: ".athing"
      - extract:
          selector: ".athing"
          fields:
            - title: ".titleline a"
            - url: ".titleline a[href]"
            - by: ".hnuser"
            - time: ".age a"

  - name: comments
    description: "取得文章評論"
    args:
      - name: id
        type: string
        required: true
      - name: limit
        type: number
        default: 20
    steps:
      - navigate: "${baseUrl}/item?id=${args.id}"
      - wait:
          selector: ".comment"
      - extract:
          selector: ".comment"
          fields:
            - author: ".hnuser"
            - text: ".commtext"
            - time: ".age a"
      - limit:
          source: "${{results}}"
          count: "${{args.limit}}"

載入並使用自製 Adapter

載入 Adapter 
# 載入 YAML Adapter
opencli plugin load ./hackernews/adapter.yaml

# 確認載入成功
opencli adapters list | grep hn

# 使用自製 Adapter
opencli hn top --limit 20
opencli hn new --limit 10
opencli hn comments 12345678 --limit 30

測試與發佈

本地測試

測試 Adapter 
# 啟用 debug 模式（顯示詳細執行步驟）
opencli --debug hn top

# 使用 dry-run（不實際操作瀏覽器）
opencli --dry-run hn search "typescript"

# 取得 Adapter 資訊
opencli adapter info hn

發佈到 npm

發佈流程 
# 初始化 npm 套件並標記為 opencli adapter
npm init
# 在 package.json 加入: "keywords": ["opencli", "opencli-adapter"]

# 發佈
npm publish

# 其他使用者安裝
npm install -g opencli-adapter-hackernews

# 載入已安裝的 Adapter
opencli plugin load opencli-adapter-hackernews

使用 AI Skill 自動生成

AI 輔助開發 Adapter 
# 安裝 adapter-author Skill
opencli skill install opencli-adapter-author

# 讓 AI 分析網站並生成 Adapter
opencli adapter-author create --url "https://lobste.rs" --output ./lobsters-adapter
💡
最佳實踐

開發 Adapter 時，建議先用 opencli browser 的通用指令手動探索網站結構，確認 selector 和操作流程後，再撰寫成 Adapter YAML。這樣可以大幅減少試錯時間。
