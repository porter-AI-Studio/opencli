Chapter 5

完整指令參考

本章系統整理 OpenCLI 所有可用指令，涵蓋 Session 管理、頁面狀態、互動操作、等待機制、資料擷取、網路監聽與 Tab 管理。每條指令均附語法說明與實用範例，可作為日常開發的快速查閱手冊。

指令結構總覽
所有 OpenCLI 瀏覽器操作均遵循統一格式： opencli browser <session> <command> [target] [options]。 其中 session 是自訂的 session 識別名稱，讓你同時管理多個瀏覽器視窗。

5.1 Session 管理

Session 是 OpenCLI 追蹤瀏覽器視窗的核心概念。每個 session 對應一個 Chrome 分頁或視窗，你可以透過 open、bind、unbind、close 四個指令完整控制其生命週期。

open — 開啟 URL 並建立 Session

open 會啟動新分頁、導覽至指定 URL，並建立一個 owned session（由 OpenCLI 管理其生命週期）。指令成功後回傳 targetId。 

opencli browser <session> open <url> [--window foreground|background]

# 範例：在前景開啟 GitHub
opencli browser gh open https://github.com --window foreground

# 範例：在背景靜默開啟登入頁
opencli browser login open https://example.com/login --window background
選項說明預設值
--window foreground開啟後立即切換到該分頁foreground
--window background在背景開啟，不切換焦點—

bind / unbind — 附加現有分頁

bind 將目前 Chrome 中活躍分頁附加到指定 session，建立 unowned session（OpenCLI 不管理其關閉）。unbind 則解除附加關係，session 記錄移除但分頁繼續存在。 

# 附加當前分頁到 session "dashboard"
opencli browser dashboard bind

# 解除附加
opencli browser dashboard unbind

close — 釋放 Session

釋放 owned session 並關閉對應視窗。對 unowned session 執行 close 只會移除 session 記錄，不會關閉分頁。 

opencli browser login close

5.2 狀態檢查

狀態指令讓你「看見」瀏覽器當前的頁面結構，是所有自動化任務的眼睛。OpenCLI 使用 ref 編號（如 [3]）標記可互動元素，後續操作可直接引用這些編號。

state — 頁面文字樹快照

擷取整頁的文字結構樹，每個可互動元素會標記 [N] ref。支援兩種資料來源：DOM 原始 HTML（dom）或 Accessibility Tree（ax，預設）。 

opencli browser <session> state [--source dom|ax] [--compare-sources]

# 使用 Accessibility Tree（預設，語意最準確）
opencli browser main state

# 使用 DOM 原始結構
opencli browser main state --source dom

# 同時顯示兩個來源並比較差異
opencli browser main state --compare-sources
何時使用 --source dom？
當頁面有自訂元件、Shadow DOM 或 ARIA 屬性不完整時，--source dom 可看到更底層的 HTML 結構，有助於找到 ax 模式下看不見的元素。

find — 查詢特定元素

使用 CSS Selector 或 ARIA 角色 + 名稱精確定位元素，回傳 ref 編號與元素資訊。 

# 以 CSS Selector 查詢
opencli browser main find --css "button[type=submit]"
opencli browser main find --css "#login-form input[name=email]"

# 以 ARIA 角色 + 名稱查詢
opencli browser main find --role button --name "登入"
opencli browser main find --role textbox --name "電子郵件"

screenshot — 截圖

擷取當前頁面截圖。加上 --annotate 會在截圖上標示所有 ref 編號，便於視覺化確認元素位置。 

# 截圖並儲存至指定路徑
opencli browser main screenshot ./screenshots/page.png

# 標註 ref 編號
opencli browser main screenshot ./screenshots/annotated.png --annotate

# 不指定路徑：輸出到 stdout（可配合 imgcat 等工具）
opencli browser main screenshot

5.3 讀取資訊

get 系列指令用於讀取頁面或特定元素的資訊，不執行任何互動操作。 

# 讀取頁面標題
opencli browser main get title

# 讀取當前 URL
opencli browser main get url

# 讀取整頁文字內容
opencli browser main get text

# 讀取特定元素的值（搭配 ref）
opencli browser main get value [3]

# 讀取元素的所有 HTML 屬性
opencli browser main get attributes [5]

# 讀取元素的 innerHTML
opencli browser main get html [7]
子指令說明適用對象
title頁面 <title> 標籤內容頁面
url當前完整 URL頁面
text可見文字內容頁面 / 元素
valueinput / select 的值表單元素
attributes所有 HTML 屬性鍵值元素
htmlinnerHTML 原始 HTML元素

5.4 互動操作

互動指令模擬真實使用者行為，觸發 JavaScript 事件。目標元素可使用 ref 編號（[N]）、CSS Selector 或 ARIA 屬性描述。

click — 點擊元素

opencli browser <session> click <target> [--nth N]

# 以 ref 點擊
opencli browser main click [3]

# 以 CSS Selector 點擊（若有多個符合，預設點第一個）
opencli browser main click "button.submit"

# 點擊第二個符合的元素
opencli browser main click "li.item" --nth 2

type vs fill — 文字輸入（重要差異）

OpenCLI 提供兩種輸入文字的方式，行為有根本差異，選錯會導致自動化失敗。

type 與 fill 的選擇至關重要
搜尋框、地址列等需要觸發 autocomplete 的欄位必須用 type；密碼欄位、固定格式輸入（日期、ID）則用 fill，效率更高且更穩定。 
# type：逐字模擬鍵盤輸入，觸發 input/keydown/keyup 事件
opencli browser main type [4] "台北市"

# fill：直接替換 value，不觸發按鍵事件
opencli browser main fill [6] "porter@example.com"
比較項目typefill
輸入方式逐字元模擬鍵盤直接設定 value
觸發事件keydown、keypress、keyup、inputinput、change
Autocomplete✅ 觸發❌ 不觸發
輸入速度較慢（逐字）即時完成
適用場景搜尋框、自動完成、地址輸入密碼、Email、固定格式欄位
清除原有內容保留（附加在後）自動清除後替換

select — 選擇下拉選項

專為原生 HTML <select> 元素設計，透過選項文字或 value 選擇。 

# 以選項顯示文字選擇
opencli browser main select [8] "台灣"

# 以 value 屬性選擇
opencli browser main select "#country" "TW"

keys — 發送鍵盤事件

模擬鍵盤快捷鍵或特殊按鍵，支援組合鍵語法。 

# 按下 Enter
opencli browser main keys Enter

# 按下 Escape
opencli browser main keys Escape

# Ctrl+A（全選）
opencli browser main keys "Control+a"

# Ctrl+C（複製）
opencli browser main keys "Control+c"

# Tab 鍵移動焦點
opencli browser main keys Tab

其他互動指令速查

指令語法說明
hoverhover <target>滑鼠移入元素，觸發 hover 狀態
focusfocus <target>設定鍵盤焦點至元素
dblclickdblclick <target>雙擊元素
checkcheck <target>勾選 checkbox 或 radio
uncheckuncheck <target>取消勾選 checkbox
uploadupload <target> <filepath>上傳本機檔案至 file input
dragdrag <source> <target>拖曳元素到另一元素
scrollscroll <target> <direction> <amount>捲動頁面或元素
backback瀏覽器上一頁
 
# hover 觸發下拉選單
opencli browser main hover "[data-menu=products]"

# 上傳圖片
opencli browser main upload [12] ./avatar.png

# 拖曳排序
opencli browser main drag [item-1] [item-3]

# 向下捲動 500px
opencli browser main scroll body down 500

5.5 等待機制

網頁操作常需要等待非同步事件完成。OpenCLI 提供四種等待策略，避免使用固定 sleep 造成的不穩定。 

# 等待 CSS selector 出現在 DOM（預設 timeout 5000ms）
opencli browser main wait selector ".success-message"
opencli browser main wait selector "#result-table" --timeout 10000

# 等待頁面出現特定文字
opencli browser main wait text "登入成功"
opencli browser main wait text "訂單已送出"

# 等待檔案下載完成
opencli browser main wait download
opencli browser main wait download "report-*.pdf"

# 固定等待秒數（盡量避免，優先使用上述三種）
opencli browser main wait time 2
等待類型適用場景建議優先度
wait selector等待 AJAX 載入的元素出現⭐⭐⭐ 優先使用
wait text等待特定提示文字顯示⭐⭐⭐ 優先使用
wait download等待下載觸發完成⭐⭐ 按需使用
wait time無條件等待（最後手段）⭐ 盡量避免

5.6 資料擷取

extract — 轉為 Markdown

將頁面或指定區域的 HTML 內容轉換為結構化 Markdown，方便後續 LLM 處理或存檔。支援大頁面的分段擷取。 

# 擷取整頁內容
opencli browser main extract

# 擷取特定區域
opencli browser main extract --selector "article.main-content"
opencli browser main extract --selector "#product-table"

# 分段擷取（每段 2000 字元）
opencli browser main extract --chunk-size 2000

# 從第 3 段開始擷取
opencli browser main extract --chunk-size 2000 --start 3

eval — 執行 JavaScript

在頁面 context 中執行任意 JavaScript，回傳執行結果。設計為唯讀操作，適合讀取複雜資料結構，不建議用於觸發副作用。 

# 讀取 localStorage
opencli browser main eval "localStorage.getItem('token')"

# 讀取 DOM 元素數量
opencli browser main eval "document.querySelectorAll('tr').length"

# 在特定 iframe 中執行
opencli browser main eval "document.title" --frame 1

# 讀取全域變數
opencli browser main eval "window.__APP_CONFIG__"
eval 使用注意事項
eval 雖然可以執行任何 JS，但應僅用於讀取資料。若需要觸發點擊或修改 DOM，請使用 click、fill 等語意明確的指令，以確保事件正確觸發且操作可追蹤。

5.7 Network 監聽

network 指令擷取瀏覽器最近的網路請求記錄，可用於驗證 API 呼叫、擷取 response body 或分析請求參數。 

# 列出最近的網路請求
opencli browser main network

# 顯示所有請求（包含靜態資源）
opencli browser main network --all

# 篩選只顯示特定欄位
opencli browser main network --filter "url,status,method"

# 取得特定請求的詳細內容（response body 等）
opencli browser main network --detail responseBody

# 顯示原始 JSON 格式
opencli browser main network --raw

# 只保留最近 5000ms 內的請求
opencli browser main network --ttl 5000
選項說明
--detail <key>展開特定欄位詳細資料（如 responseBody、requestHeaders）
--filter <fields>逗號分隔，只顯示指定欄位
--all包含圖片、CSS、JS 等靜態資源請求
--raw輸出未格式化的原始 JSON
--ttl <ms>只保留指定毫秒內的新請求

5.8 Tab 管理

當需要同時操作多個分頁時，可使用 tab 系列指令管理分頁生命週期。 

# 列出所有開啟的分頁
opencli browser main tab list

# 開啟新分頁（不指定 URL 則開啟空白頁）
opencli browser main tab new
opencli browser main tab new https://example.com

# 切換到指定分頁（使用 targetId）
opencli browser main tab select ABC123targetId

# 關閉指定分頁
opencli browser main tab close ABC123targetId

5.9 全域參數速查表

以下參數適用於大多數 OpenCLI 指令，可組合使用以精確控制行為。

參數說明範例
--nth N當多個元素符合時，選取第 N 個（從 1 起算）--nth 2
--frame N在第 N 個 iframe 內操作--frame 1
--tab <targetId>指定操作目標分頁--tab ABC123
--timeout <ms>覆蓋預設逾時時間（毫秒）--timeout 15000
--role <role>以 ARIA role 定位元素--role button
--name <name>以 ARIA accessible name 定位--name "送出"
--label <text>以 <label> 文字定位關聯 input--label "姓名"
--testid <id>以 data-testid 屬性定位--testid "submit-btn"
-f / --format輸出格式：table、json、yaml、md、csv-f json
 
# 組合使用：在第 2 個 iframe 內點擊第 3 個符合的按鈕，15 秒逾時
opencli browser main click "button.action" --frame 1 --nth 3 --timeout 15000

# 以 ARIA 定位並以 JSON 輸出
opencli browser main find --role textbox --name "搜尋" -f json

# 以 data-testid 精確定位
opencli browser main click --testid "checkout-button"

5.10 Match Level — Ref 匹配信心度

OpenCLI 使用 ref 編號（[N]）跨指令追蹤元素。由於頁面可能在操作間更新，系統以 Match Level 回報 ref 的匹配可靠度。

Match Level說明建議行動
exactRef 完全對應，元素未變動直接操作，最可靠
stable元素存在但部分屬性有輕微變化可繼續操作，注意結果
reidentified原 ref 失效，系統透過啟發式重新找到元素建議重新執行 state 取得新 ref
何時會出現 reidentified？
SPA 路由切換、React/Vue 重新渲染、AJAX 局部更新後，原本的 ref 可能失效。系統會嘗試重新定位，但建議在重大頁面變化後重新執行 state 取得最新 ref，確保操作準確。

5.11 錯誤碼對照表

當指令執行失敗時，OpenCLI 回傳結構化錯誤碼，方便在 script 中進行條件判斷與錯誤處理。

錯誤碼說明常見原因與解法
not_found 找不到指定 session 先執行 open 或 bind 建立 session
stale_ref Ref 編號已失效（元素不再存在） 重新執行 state 取得最新 ref
invalid_selector CSS Selector 語法錯誤 檢查 selector 語法，特殊字元需跳脫
selector_not_found Selector 語法正確但找不到符合元素 確認頁面已載入完成，或使用 wait selector
selector_ambiguous Selector 符合多個元素 加上 --nth N 指定，或使用更精確的 selector
option_not_found select 找不到指定選項 確認選項文字或 value 完全符合（區分大小寫）

5.12 完整工作流範例：自動化登入流程

以下範例整合本章所有核心指令，示範一個完整的登入自動化流程，包含錯誤處理與狀態驗證。 

#!/bin/bash
# 完整登入自動化流程範例

SESSION="login-flow"
BASE_URL="https://app.example.com"

echo "=== 步驟 1：開啟登入頁面 ==="
opencli browser ${SESSION} open "${BASE_URL}/login" --window foreground

echo "=== 步驟 2：等待登入表單載入 ==="
opencli browser ${SESSION} wait selector "#login-form" --timeout 10000

echo "=== 步驟 3：截圖確認頁面狀態 ==="
opencli browser ${SESSION} screenshot ./debug/before-login.png --annotate

echo "=== 步驟 4：檢視頁面結構，取得 ref 編號 ==="
opencli browser ${SESSION} state

echo "=== 步驟 5：填入電子郵件（fill，不需 autocomplete）==="
opencli browser ${SESSION} fill --label "電子郵件" "porter@example.com"

echo "=== 步驟 6：填入密碼（fill，不需 autocomplete）==="
opencli browser ${SESSION} fill --label "密碼" "MySecret123!"

echo "=== 步驟 7：確認記住我核取方塊 ==="
opencli browser ${SESSION} check --label "記住我"

echo "=== 步驟 8：點擊登入按鈕 ==="
opencli browser ${SESSION} click --role button --name "登入"

echo "=== 步驟 9：等待登入成功訊息或儀表板載入 ==="
opencli browser ${SESSION} wait text "歡迎回來" --timeout 8000

echo "=== 步驟 10：驗證當前 URL 已跳轉 ==="
CURRENT_URL=$(opencli browser ${SESSION} get url)
echo "當前 URL：${CURRENT_URL}"

echo "=== 步驟 11：擷取儀表板主要內容 ==="
opencli browser ${SESSION} extract --selector "main.dashboard"

echo "=== 步驟 12：確認 API token 已寫入 localStorage ==="
TOKEN=$(opencli browser ${SESSION} eval "localStorage.getItem('auth_token')")
echo "Token 長度：${#TOKEN}"

echo "=== 步驟 13：截圖存檔 ==="
opencli browser ${SESSION} screenshot ./debug/after-login.png

echo "=== 登入流程完成，釋放 session ==="
opencli browser ${SESSION} close
搜尋框使用 type 的範例
若登入後需要使用搜尋功能（有 autocomplete），應改用 type 而非 fill： 
# 搜尋框需要 autocomplete：使用 type
opencli browser ${SESSION} type --role searchbox --name "搜尋" "台北"

# 等待 autocomplete 選項出現
opencli browser ${SESSION} wait selector ".autocomplete-dropdown"

# 選擇第一個建議項目
opencli browser ${SESSION} click ".autocomplete-item" --nth 1

工作流最佳實踐

  • 每次操作前使用 wait selector 或 wait text 確保頁面就緒，而非使用固定 wait time
  • 密碼、固定格式欄位一律使用 fill；搜尋、地址等 autocomplete 欄位使用 type
  • 遇到 stale_ref 錯誤時，重新執行 state 取得最新 ref 後再繼續
  • 在關鍵步驟前後加上 screenshot --annotate，方便除錯時確認實際頁面狀態
  • 使用 network 指令驗證 API 呼叫是否成功，而非僅依賴 UI 文字判斷
  • 長時間流程中，使用 -f json 格式輸出，方便 shell script 解析結果
