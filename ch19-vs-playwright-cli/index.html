第 19 章 · Part 6：比較與實戰

OpenCLI vs Playwright CLI

微軟在 2026 年推出 @playwright/cli，同樣定位為「給 AI Coding Agent 使用的 CLI 瀏覽器工具」。兩者設計理念相近，但核心哲學截然不同—— 一個說「我要什麼」，另一個說「我看到什麼、我要點哪裡」。

19.1 兩個工具的定位

先看最能體現兩者差異的一個對比：同樣是「取得 GitHub 熱門 TypeScript 專案」：

OpenCLI

opencli github trending --language typescript

告訴工具「我要什麼」。Adapter 封裝了平台知識，無需了解頁面結構。

Playwright CLI

open → snapshot → select e3 "TypeScript" → snapshot → eval e5

告訴工具「我看到什麼、我要怎麼做」。透過 snapshot 理解頁面，再根據元素 ref 操作。

這個差異反映了兩者的根本設計取向：

  • OpenCLI：語義優先。Adapter 是知識庫，封裝了平台的操作邏輯，使用者只需表達意圖。
  • Playwright CLI：通用優先。任何網站都能操作，但需要先「看懂頁面」（snapshot），再根據視覺結構互動。

19.2 安裝方式

OpenCLI 
npm install -g opencli
opencli --version
Playwright CLI（@playwright/cli） 
npm install -g @playwright/cli@latest
playwright-cli --version

# 安裝瀏覽器引擎（首次需要）
npx playwright install
ℹ️
Playwright CLI 需要額外安裝瀏覽器引擎

npx playwright install 會下載 Chromium / Firefox / WebKit 等引擎（約 200–500 MB）。 OpenCLI 連線至已在執行中的 Chrome，不需要額外下載瀏覽器。

19.3 Playwright CLI 的核心機制：Snapshot 驅動

Playwright CLI 最核心的設計是 Snapshot 驅動： 每次操作前先呼叫 snapshot，工具掃描頁面並回傳結構化的元素清單， 每個可互動元素都有一個臨時 ref（e1、e2...）。 後續操作都基於這些 ref，而非 CSS selector。

Snapshot 驅動工作流程 
# Step 1：打開頁面
playwright-cli open https://github.com/trending

# Step 2：取得 snapshot（回傳結構化元素列表，每個元素有 ref）
playwright-cli snapshot
# 輸出範例（截取）:
# - e1 [link] "Explore GitHub" href=/explore
# - e3 [select] language selector
# - e5 [link] "microsoft/typescript" href=/microsoft/typescript
# - e6 [text] "⭐ 98,432 stars this week"
# ...

# Step 3：基於 ref 操作（不需要寫 CSS selector！）
playwright-cli select e3 "TypeScript"    # 切換語言篩選
playwright-cli snapshot                  # 取得更新後列表
playwright-cli eval "el => el.textContent" e5  # 讀取 repo 名稱
💡
為什麼 Snapshot 比 CSS Selector 更適合 AI Agent？

CSS selector 會隨版本更新而失效（如 data-testid 名稱常改變）。 Snapshot ref 是基於頁面當前的語意結構動態產生， 即使 class 名稱改變，只要頁面語意不變，ref 仍然可用。 更重要的是，AI Agent 不需要學習 CSS 就能理解「e5 是登入按鈕」。

19.4 核心工作流程對比

已知平台 vs 任意網站

OpenCLI — 已知平台，語義直達 
# 已知平台：語義指令，1 行搞定
opencli twitter trending --limit 10
opencli github trending --language typescript
opencli youtube search "Astro framework" --limit 5
Playwright CLI — 任意網站，snapshot 探索 
# 任意網站：snapshot → ref → 操作
playwright-cli open https://twitter.com/explore
playwright-cli snapshot          # 取得 e1, e2, e3... 元素引用
playwright-cli click e7          # 點擊 Trending 區塊
playwright-cli snapshot          # 取得新狀態
playwright-cli eval "document.querySelectorAll('[data-testid=trend]').length"

表單互動對比

OpenCLI browser 模式 
# OpenCLI 的 browser 模式（任意網站）
opencli browser open https://example.com/login
opencli browser find "input[name=email]"
opencli browser type "N1" "user@example.com"
opencli browser type "N2" "password123"
opencli browser click "button[type=submit]"
Playwright CLI snapshot-ref 方式 
# Playwright CLI 的 snapshot-ref 方式
playwright-cli open https://example.com/login
playwright-cli snapshot
# → e1 [input] email, e2 [input] password, e3 [button] Login
playwright-cli fill e1 "user@example.com"
playwright-cli fill e2 "password123" --submit  # --submit 自動按 Enter

19.5 Playwright CLI 的獨特功能

自動生成 TypeScript 程式碼

Playwright CLI 的殺手級功能：每個操作自動輸出對應的 Playwright TypeScript 程式碼。 你可以用 CLI 探索頁面，完成後把生成的程式碼直接放進 Playwright 測試套件。

操作 → 程式碼自動生成 
# 每個 playwright-cli 操作都自動輸出對應的 TypeScript 程式碼
playwright-cli click e3

# 輸出：
# Ran Playwright code:
# ─────────────────────────────────────
# await page.getByRole('link', { name: 'TypeScript' }).click();
# ─────────────────────────────────────
# Generated code saved to: .playwright-cli/actions.ts
💡
最佳使用場景

需要為新頁面編寫 Playwright E2E 測試時，先用 playwright-cli 互動式探索， 收集所有 ref 操作後，生成的 TypeScript 就是 90% 完成的測試腳本。 比手寫選擇器快 3–5 倍。

網路 Mock 與路由攔截

Playwright CLI 支援完整的請求攔截，OpenCLI 目前無此對應功能：

網路 Mock（Playwright CLI 獨有） 
# Playwright CLI 支援完整的網路 Mock（OpenCLI 無此功能）
playwright-cli route "https://api.example.com/**" \
  --body='{"mock":true,"data":[]}' \
  --content-type=application/json

# 模擬 404
playwright-cli route "**/avatar.png" --status=404

# 移除所有 Mock
playwright-cli unroute

Session 管理

OpenCLI — Profile 模式 
# OpenCLI：profile 概念，自動保存登入狀態
opencli browser start --profile=work
# 之後所有指令自動沿用 work profile 的 cookies/localStorage
Playwright CLI — 命名 Session 
# Playwright CLI：命名 session，獨立隔離
playwright-cli -s=github open https://github.com/login
playwright-cli -s=github fill e1 "username"
playwright-cli -s=github fill e2 "password"
playwright-cli -s=github click e3

# 保存 / 載入 session 狀態
playwright-cli -s=github state-save github-auth.json
playwright-cli -s=github state-load github-auth.json  # 之後重用

19.6 AI Agent 整合比較

兩個工具都聲稱為 AI Coding Agent 設計，但整合方式不同：

OpenCLI — 語義工具調用 
# Claude Code 呼叫 OpenCLI skill（語義指令）
# claude code 的 skill 描述：
# "搜尋 GitHub 熱門 TypeScript 專案"
# → Claude 直接執行：
opencli github trending --language typescript --limit 10 --json
Playwright CLI — Snapshot 感知循環 
# Claude Code 呼叫 playwright-cli skill（snapshot 驅動）
# claude code 的 skill 描述：
# "在任意網站上操作表單或擷取資料"
# → Claude 先 snapshot 理解頁面，再根據 ref 操作：
playwright-cli open https://some-internal-tool.com
playwright-cli snapshot
# Claude 讀取 snapshot 輸出，決定下一步操作
playwright-cli click e12
playwright-cli fill e15 "query text"
AI Agent 整合維度 OpenCLI Playwright CLI
指令可預測性 高（語義指令固定） 中（需先 snapshot 才知道 ref）
Token 消耗 極低（1 行語義指令） 低（snapshot 比 accessibility tree 省）
通用性 受限於 Adapter 支援的平台 任何網站均可操作
Agent 決策複雜度 低（知道指令名稱即可） 中（需閱讀 snapshot 決定 ref）
輸出結構化程度 JSON / CSV（由 Adapter 定義） 文字 + 自動生成 TS 程式碼
Skills 安裝 opencli skills install playwright-cli install --skills

19.8 工具選擇決策樹

OpenCLI vs Playwright CLI 決策指南 
需要 CLI 瀏覽器自動化？
│
├─ 目標是已知平台（Twitter / GitHub / YouTube / Bilibili 等）？
│  └─ 是 → OpenCLI（語義指令，零選擇器知識）✅
│
├─ 目標是內部系統 / 任意網站，需要 AI Agent 互動？
│  ├─ 會生成 Playwright 測試程式碼的需求？ → Playwright CLI ✅
│  └─ 純操作不需要程式碼 → OpenCLI browser 模式 or Playwright CLI
│
├─ 需要 Network Mock / 路由攔截？
│  └─ 是 → Playwright CLI（OpenCLI 目前無此功能）✅
│
├─ 需要多個獨立隔離的瀏覽器 Session 同時並行？
│  └─ 是 → Playwright CLI（-s=name 命名 session）✅
│
├─ AI Agent 工具調用，需要 token 最省？
│  ├─ 已知平台 → OpenCLI（語義指令，1 行 = 1 token 描述）✅
│  └─ 未知頁面 → Playwright CLI（snapshot 比 accessibility tree 更省 token）✅
│
└─ 需要截圖 / PDF / 追蹤 / 錄影？
   └─ 是 → Playwright CLI（screenshot, pdf, tracing-start, video-start）✅

19.9 搭配使用：OpenCLI 探索 + Playwright CLI 生成程式碼

兩個工具互補性很強——OpenCLI 快速取得入口資料，Playwright CLI 負責深度互動並輸出可重用的程式碼：

hybrid-discovery.sh — 語義搜尋 + snapshot 深度操作 
#!/usr/bin/env bash
# hybrid-discovery.sh
# 用 OpenCLI 找到目標 URL → 用 Playwright CLI 深度互動 + 生成測試程式碼

# Step 1：OpenCLI 語義搜尋（快速，不需要 snapshot）
TARGET_URL=$(opencli github trending --language rust --limit 1 --json | jq -r '.[0].url')
echo "Target: $TARGET_URL"

# Step 2：Playwright CLI 開啟並拍快照（任意頁面結構探索）
playwright-cli open "$TARGET_URL"
playwright-cli snapshot > page-snapshot.txt

# Step 3：基於 snapshot 讓 AI Agent 決定如何互動
# （Claude Code 讀取 page-snapshot.txt 後決定 ref）
playwright-cli click e8       # 例：點擊 Star 按鈕
playwright-cli screenshot --filename="result.png"

echo "Done. Generated TS code in .playwright-cli/actions.ts"
ℹ️
典型使用案例

在建立新平台的 Custom Adapter 時，先用 playwright-cli 探索目標頁面的結構、 取得 snapshot ref、確認互動路徑，生成的 TypeScript 程式碼直接作為 Adapter 實作的骨架。 這個流程可以把 Adapter 開發時間從幾小時縮短到幾十分鐘。

19.10 本章小結

OpenCLI 與 Playwright CLI 都是為 AI Agent 設計的 CLI 瀏覽器工具，但面向不同的問題：

  • OpenCLI：已知平台的語義自動化。當你知道「我要什麼」，1 行搞定。
  • Playwright CLI：任意網站的通用探索。當你面對未知頁面，snapshot 讓 AI 「看見」頁面結構後再行動。
  • Playwright CLI 的程式碼生成功能是 OpenCLI 沒有的：它是探索 → 生成測試腳本的最佳橋樑。
  • 搭配策略：OpenCLI 處理已知平台日常操作，Playwright CLI 處理未知頁面探索與 Adapter 開發的啟動期。
