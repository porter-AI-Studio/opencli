第 4 章 · Part 2：瀏覽器自動化

連接瀏覽器與 Session 管理

掌握 Session 生命週期，讓 OpenCLI 穩定控制瀏覽器分頁——從單一任務到多工並行，一次搞懂。

💡
本章重點

本章著重在「如何與瀏覽器建立連線」以及「Session 的管理策略」。指令操作的細節（click、type、extract 等）留待第 5 章完整參考。

架構概覽

在動手操作之前，先了解 OpenCLI 是如何與 Chrome 瀏覽器溝通的。整個架構由三層組成：

OpenCLI 連線架構 
使用者 / AI Agent
      ↓  （輸入指令）
  opencli CLI
      ↓  （HTTP / WebSocket）
  opencli daemon  ←→  localhost:19825
      ↓  （CDP / WebSocket）
Browser Bridge Extension
      ↓  （Chrome DevTools Protocol）
  Chrome 瀏覽器（已登入的 session）

這三層分別負責：

  • opencli CLI：你在終端機輸入的指令，負責解析並轉發給 daemon。
  • opencli daemon：常駐背景的本地伺服器，預設監聽 localhost:19825，負責維護所有 Session 狀態並橋接 Chrome。
  • Browser Bridge Extension：安裝在 Chrome 的擴充功能，透過 CDP（Chrome DevTools Protocol）接收 daemon 的指令並操作頁面。
為什麼需要 Extension？
CDP 直接連線到 Chrome 需要在啟動時加入 --remote-debugging-port 旗標，會破壞現有的瀏覽器 profile。Browser Bridge Extension 讓 OpenCLI 能附著到任何已開啟的 Chrome 視窗，包含你已登入所有網站的日常瀏覽器。

Session 核心概念

Session 是 OpenCLI 管理瀏覽器分頁的基本單位。每個 Session 對應到 Chrome 中的一個分頁， 並以一個自訂名稱識別。相同名稱的指令會操作同一個分頁，不同名稱之間完全隔離。

Session 名稱就是 opencli browser 指令的第二個位置參數：

Session 名稱的位置 
#                  ↓ 這是 session 名稱
opencli browser  <name>  <subcommand> [options]

# 範例：session 名稱為 "work"
opencli browser work open https://github.com
opencli browser work state
opencli browser work click ".repository-content"

Owned vs Unowned Session

OpenCLI 的 Session 分兩種，差異在於誰負責管理分頁的生命週期：

類型 建立方式 執行 close 後 適用情境
owned open 指令 關閉分頁 + 移除記錄 自動化腳本、CI 任務
unowned bind 指令 只移除記錄，分頁繼續 附著已登入的分頁

Session 生命週期

open — 開啟 URL 並建立 Owned Session

open 會在 Chrome 建立新分頁並導向指定 URL，Session 類型為 owned。 OpenCLI 全權管理這個分頁的關閉。

open 指令語法 
opencli browser <session> open <url> [--window foreground|background]
open 實際範例 
# 在前景開啟 GitHub（預設行為，開啟後立即切換到該分頁）
opencli browser gh open https://github.com --window foreground

# 在背景靜默開啟登入頁（不切換焦點，適合批次任務）
opencli browser login open https://example.com/login --window background

# session 名稱可以是任意字串
opencli browser research open https://arxiv.org

--window 選項說明：

  • foreground（預設）：開啟後立即將 Chrome 切換到該分頁。
  • background：在背景開啟分頁，不影響目前的前景視窗。

bind / unbind — 附著現有分頁

如果你想操作瀏覽器中已經開好的分頁（例如已登入 Gmail 的分頁）， 使用 bind 建立 unowned session，OpenCLI 不會管理分頁的關閉。

bind / unbind 語法與範例 
# 將當前瀏覽器最前景的分頁附著為 session "dashboard"
opencli browser dashboard bind

# 操作剛才 bind 的分頁
opencli browser dashboard state
opencli browser dashboard click ".compose-btn"

# 解除附著：移除 session 記錄，但 Chrome 分頁繼續存在
opencli browser dashboard unbind
💡
bind 的典型用途

你已經登入 Gmail、Notion、Slack……等網站，不想重新登入，又想讓 AI Agent 操作這些頁面。用 bind 把分頁接管過來，操作完後 unbind，分頁依然在你的瀏覽器裡。

close — 釋放 Session

close 的行為因 Session 類型而異：

close 指令 
# 釋放 session（owned → 關閉分頁；unowned → 只移除記錄）
opencli browser login close
opencli browser dashboard close

使用原則：每個 open 或 bind 都應搭配對應的 close，避免 daemon 累積過多懸空的 Session 記錄。

同時管理多個 Session

OpenCLI 的 Session 模型天生支援多工。你可以同時開啟多個 Session，各別操作， 再統一關閉——這是 AI Agent 平行作業的基礎。

多 Session 並行範例 
# 同時開啟三個工作區
opencli browser github open https://github.com
opencli browser notion open https://notion.so
opencli browser slack  open https://app.slack.com

# 各別操作，互不干擾
opencli browser github state
opencli browser notion click ".new-page-btn"
opencli browser slack  find "input[data-qa='message_input']"

# 需要時查看所有 session
opencli browser list

# 任務完成，統一關閉
opencli browser github close
opencli browser notion close
opencli browser slack  close
N 索引（N-ref）與多 Session
每個 Session 的 N 索引是獨立的快照，執行 state 後產生，隨頁面更新而重新編號。 跨 Session 的 N 索引互不相關，不會產生衝突。自動化腳本若需要穩定的元素定位，建議改用 CSS selector（例如 ".submit-btn"）；N 索引最適合人工探索頁面時使用。

Daemon 管理

Daemon 是 OpenCLI 的核心服務，預設在你第一次執行指令時自動啟動。 大多數情況下你不需要手動管理，但遇到連線問題時，以下指令會很有用：

Daemon 管理指令 
# 查看 daemon 狀態（確認是否在跑、監聽哪個 port）
opencli daemon status

# 手動啟動（通常會自動啟動，但某些 CI 環境需要明確執行）
opencli daemon start

# 重啟（遇到連線異常的萬用解法）
opencli daemon restart

# 一鍵健康檢查（daemon + Extension + Chrome 全部檢查）
opencli doctor

opencli doctor 是診斷連線問題的首選工具，它會逐項檢查： daemon 是否在跑、Browser Bridge Extension 是否安裝並啟用、Chrome 是否開啟並可連線。

opencli doctor 正常輸出示意 
✅  daemon          running on localhost:19825
✅  extension        connected (Browser Bridge v1.4.2)
✅  chrome           1 window, 3 tabs
✅  all checks passed

CI 環境與遠端 CDP 連線

在 CI/CD 環境（GitHub Actions、Jenkins 等）中，Chrome 通常以 headless 模式啟動， 並透過 CDP WebSocket 對外暴露端口。OpenCLI 支援透過環境變數指定遠端 CDP endpoint：

CI 環境：指定遠端 CDP endpoint 
# 設定環境變數，讓 OpenCLI 連線到遠端 CDP
export OPENCLI_CDP_ENDPOINT=ws://localhost:3000

# 之後的指令皆透過該 CDP endpoint 運作
opencli browser work open https://example.com
opencli browser work state
GitHub Actions 範例片段 
- name: Launch Chrome with CDP
  run: |
    google-chrome-stable \
      --headless \
      --remote-debugging-port=3000 \
      --no-sandbox &
    sleep 2  # 等待 Chrome 就緒

- name: Run OpenCLI automation
  env:
    OPENCLI_CDP_ENDPOINT: ws://localhost:3000
  run: |
    opencli browser test open https://staging.example.com
    opencli browser test wait --selector ".page-loaded"
    opencli browser test screenshot --output result.png
⚠️
CI 環境的 Extension 限制

Browser Bridge Extension 需要安裝到 Chrome profile，headless CI 環境通常沒有 profile。在 CI 中建議直接使用 OPENCLI_CDP_ENDPOINT 模式，繞過 Extension 直接連線 CDP。

疑難排解：常見連線問題

症狀 可能原因 解法
Extension: not connected Chrome 沒裝 Browser Bridge Extension，或 Chrome 未開啟 安裝擴充功能、開啟 Chrome、執行 opencli daemon restart
Connection refused Daemon 沒有在跑 執行 opencli daemon start 或 opencli doctor
UNABLE_TO_VERIFY_LEAF_SIGNATURE 公司網路 MITM SSL 攔截 設定 NODE_OPTIONS（見下方）

修復 MITM SSL 問題（公司 / 企業網路）

企業環境常部署 SSL inspection proxy，會導致 Node.js 驗證 TLS 憑證失敗。 解法是告訴 Node.js 使用系統憑證庫：

Windows（PowerShell） 
# 暫時設定（當前 session 有效）
$env:NODE_OPTIONS = "--use-system-ca"

# 永久設定（寫入系統環境變數）
[System.Environment]::SetEnvironmentVariable("NODE_OPTIONS", "--use-system-ca", "User")
macOS / Linux（bash/zsh） 
# 暫時設定
export NODE_OPTIONS="--use-system-ca"

# 永久設定（加到 ~/.bashrc 或 ~/.zshrc）
echo 'export NODE_OPTIONS="--use-system-ca"' >> ~/.zshrc

Session 狀態不一致

若遇到指令回報 Session 存在但實際分頁已關閉，或相反情況，可以強制重置：

清除殘留 Session 記錄 
# 查看目前所有 session
opencli browser list

# 逐一關閉殘留的 session（即使分頁已不存在）
opencli browser <name> close

# 或直接重啟 daemon，清除所有 session 狀態
opencli daemon restart

Session 管理最佳實踐

  1. 命名反映任務：使用有意義的 session 名稱（github、billing、test-form）， 而非通用名稱（tab1、session）。在 AI Agent 的長時間任務中，清楚的命名能大幅降低操作錯分頁的風險。
  2. 腳本結尾務必 close：自動化腳本應在 finally/trap 區塊確保 Session 被關閉， 避免每次執行都累積孤立的分頁與記錄。
  3. bind 保留登入狀態：需要已登入帳號的網站（Gmail、Notion、公司內網）， 用 bind 附著現有分頁，不要用 open 開新頁重新登入。
  4. 背景開啟減少干擾：批次開啟多個 Session 時，加上 --window background 避免 Chrome 視窗頻繁跳到前景。
健壯腳本範例（帶清理） 
#!/bin/bash
# 確保腳本退出時自動關閉 session
trap 'opencli browser task close 2>/dev/null' EXIT

opencli browser task open https://example.com/dashboard --window background
opencli browser task wait --selector ".dashboard-loaded"
opencli browser task screenshot --output report.png

echo "任務完成，截圖已儲存為 report.png"
