第 20 章 · Part 6：比較與實戰

OpenCLI vs Playwright MCP

同樣是讓 AI 控制瀏覽器，但 CLI Daemon 架構與 MCP Server 架構背後的設計理念截然不同。本章深入剖析兩者的差異與各自的最佳應用場景。

20.1 兩個工具的定位

OpenCLI 是一個 CLI 工具，透過 Daemon 常駐程序 + Browser Extension，讓開發者（或 AI）在終端機以語義指令操作瀏覽器。它提供 30+ 個平台 Adapter，讓 opencli twitter post 這樣的高層語義指令直接可用。

Playwright MCP 是 Microsoft 開源的 MCP Server，讓支援 MCP 協定的 AI 客戶端（Claude Code、VS Code Copilot、Cursor 等）直接呼叫瀏覽器自動化工具，不需要 CLI 子程序。它基於 Accessibility Tree（無障礙樹）快照，不依賴視覺模型。

ℹ️
Playwright MCP vs Playwright CLI

注意：Playwright 生態有兩個工具都叫「Playwright CLI」。本章比較的是 @playwright/mcp（MCP Server，AI 工具整合）。上一章（Ch 19）比較的是 @playwright/cli（互動式 Snapshot CLI）。兩者完全不同。

20.2 架構差異：Daemon + Extension vs MCP Server

兩者的底層架構決定了它們的使用方式：

架構對比 
OpenCLI 架構：
  開發者 / AI
       ↓ CLI 指令
  opencli process
       ↓ WebSocket
  Daemon（7070 port）
       ↓ Chrome Extension Protocol
  Browser Extension ↔ 已開啟的 Chrome 分頁

Playwright MCP 架構：
  AI Client（Claude Code / Cursor / VS Code Copilot）
       ↓ MCP 工具呼叫（JSON-RPC 2.0）
  @playwright/mcp Server Process
       ↓ Playwright API
  Playwright 控制的瀏覽器（獨立或 headed/headless）

關鍵差異：OpenCLI 附著在你已開啟的 Chrome 視窗上，而 Playwright MCP 自己啟動一個獨立的瀏覽器實例。

20.3 安裝與設定

OpenCLI 安裝 
npm install -g opencli
opencli --version
Playwright MCP 安裝 
# 在 Claude Code 中加入（推薦）
claude mcp add playwright npx @playwright/mcp@latest

# 或在 VS Code CLI
code --add-mcp '{"name":"playwright","command":"npx","args":["@playwright/mcp@latest"]}'

# 或手動加入 MCP 設定檔（Claude Desktop、Cursor 等）
# {
#   "mcpServers": {
#     "playwright": {
#       "command": "npx",
#       "args": ["@playwright/mcp@latest"]
#     }
#   }
# }

OpenCLI 安裝後需要另外在 Chrome 安裝 Browser Bridge Extension；Playwright MCP 只需在 AI 客戶端加入一行設定，無需安裝瀏覽器外掛。

20.4 核心機制：N-ref vs Accessibility Tree Snapshot

兩個工具的「元素定位」方式有本質差異：

OpenCLI：N-ref 語義標記 
# OpenCLI 運作模型
# 1. 啟動 daemon（連接瀏覽器）
opencli daemon start

# 2. 取得頁面狀態（N-ref）
opencli browser work state
# 輸出：
# [1] input#search "搜尋..."
# [2] button "登入"
# [3] a "首頁"

# 3. 基於 N-ref 操作
opencli browser work type "[1]" "OpenCLI"
opencli browser work click "[2]"
Playwright MCP：Accessibility Tree 快照（LLM 自動處理） 
# Playwright MCP 運作模型
# （由 AI LLM 自動呼叫，無需人工命令）

# LLM 看到的 Accessibility Tree 快照：
# - heading "todos" [level=1]
# - textbox "What needs to be done?" [ref=e5]
# - listitem:
#   - checkbox "Toggle Todo" [ref=e10]
#   - text "Buy groceries"

# LLM 自動呼叫對應工具：
# browser_fill(ref="e5", value="學習 OpenCLI")
# browser_click(ref="e10")

OpenCLI 的 N-ref 是由 人或 AI 主動讀取快照 後再執行操作；Playwright MCP 的快照由 LLM 自動解讀，它看到 ref=e5 就知道要呼叫 browser_fill(ref="e5")，整個過程對使用者透明。

💡
Playwright MCP 的兩種模式
  • Snapshot 模式（預設）：讀取 Accessibility Tree，純文字結構，速度快、不需要視覺模型
  • Vision 模式：分析截圖，適合 Canvas、複雜 CSS 背景等無障礙樹無法表達的元素，需要多模態 LLM

20.5 表單操作比較

OpenCLI：state → 命令 
# OpenCLI 方式
opencli browser open https://example.com/login
opencli browser work state
# → [1] input email  [2] input password  [3] button Login

opencli browser work type "[1]" "user@example.com"
opencli browser work type "[2]" "password123"
opencli browser work click "[3]"
Playwright MCP：自然語言 → AI 自動完成 
# Playwright MCP 方式（由 LLM 自動完成）
# 提示：「登入 https://example.com/login，帳號 user@example.com 密碼 password123」

# LLM 自動呼叫：
# browser_navigate(url="https://example.com/login")
# → 取得快照：[ref=e1] input email, [ref=e2] input password, [ref=e3] button Login
# browser_fill(ref="e1", value="user@example.com")
# browser_fill(ref="e2", value="password123")
# browser_click(ref="e3")

對於一般表單，兩者都能完成任務。主要差異在於：OpenCLI 每個步驟都需要明確指令，Playwright MCP 讓 LLM 自主決定呼叫哪些工具、按什麼順序執行。

20.6 網路攔截與 Mock

OpenCLI：network intercept 
# OpenCLI：導航前設定攔截
opencli browser work network intercept --pattern "*/api/users*"
opencli browser work navigate https://app.example.com

# 查看攔截的請求
opencli browser work network log
Playwright MCP：browser_route_fulfill（由 LLM 呼叫） 
# Playwright MCP：提示 LLM 設定 route mock
# 「導航到 https://app.example.com，
#   把所有 /api/users 的請求 mock 回傳空陣列」

# LLM 自動呼叫：
# browser_route_fulfill(
#   url="**/api/users**",
#   value={ status: 200, body: "[]" }
# )
# browser_navigate(url="https://app.example.com")

兩者都支援網路攔截，但操作方式不同：OpenCLI 需要在程式碼或腳本中明確設定攔截規則，Playwright MCP 可以用自然語言描述需求讓 LLM 自動設定。

20.7 Session 與瀏覽器狀態管理

OpenCLI：命名 Session 
# OpenCLI：命名 Session 隔離
opencli browser work open https://twitter.com    # work session
opencli browser news open https://hn.algolia.com # news session

# 各 session 各自獨立，互不干擾
opencli browser list
Playwright MCP：Profile 模式 
# Playwright MCP：三種 Profile 模式

# 預設（Persistent）：跨對話保留登入狀態
npx @playwright/mcp@latest

# 隔離模式（Isolated）：每次全新，適合測試
npx @playwright/mcp@latest --isolated

# 載入已存狀態（從之前儲存的 JSON）
npx @playwright/mcp@latest --storage-state auth.json

# 儲存目前狀態
# 提示：「儲存目前瀏覽器狀態到 auth.json」
# → LLM 呼叫 browser_save_storage_state(filename="auth.json")

OpenCLI 的命名 Session 讓你同時操控多個不同任務的分頁，邏輯清晰。Playwright MCP 的 Persistent 模式則讓 AI 跨對話記住登入狀態，更像「有記憶的助理」。

20.8 AI Agent 整合方式比較

OpenCLI：AI 透過 Bash 呼叫 CLI 
# OpenCLI：AI 呼叫 CLI 子程序
# Claude Code 中透過 Bash 工具執行 opencli 指令

async function scrapeGitHubTrending() {
  const result = await bash("opencli github trending --language typescript --json");
  return JSON.parse(result);
}
Playwright MCP：AI 直接呼叫 MCP 工具 
# Playwright MCP：AI 直接呼叫 MCP 工具
# 不需要 Bash 子程序，工具直接嵌入 AI 上下文

# Claude Code 對話（啟用 playwright MCP 後）：
# 「打開 https://github.com/trending，
#   篩選 TypeScript，截圖並回傳前 10 名 repo 名稱」
#
# → LLM 自動完成：
#   browser_navigate → browser_screenshot →
#   browser_snapshot → 解析文字 → 回傳結果

這是兩者最根本的設計差異：

  • OpenCLI：AI 是「指揮者」，透過 Bash 子程序發出 CLI 命令，每個步驟都顯式出現在 AI 的工具呼叫記錄中
  • Playwright MCP：AI 是「執行者」，工具直接嵌入 LLM 的推理上下文，AI 可以在一次思考中規劃並執行多步驟操作
⚠️
Tool Proliferation 問題

Playwright MCP 暴露了 20+ 個細粒度工具（browser_click、browser_fill、browser_navigate、browser_screenshot 等），可能讓 LLM 在工具選擇上產生決策困難（tool proliferation 問題）。OpenCLI 的語義指令數量少、語義明確，對 LLM 更友好。

20.9 E2E 測試工作流程

OpenCLI + Vitest：程式碼驅動 
# OpenCLI + Vitest：程式碼驅動的測試
import { test, expect } from 'vitest';
import { opencli } from './helpers/opencli';

test('登入流程', async () => {
  await opencli('browser open https://example.com/login');
  await opencli('browser work state');
  await opencli('browser work type "[1]" "test@example.com"');
  await opencli('browser work type "[2]" "password123"');
  await opencli('browser work click "[3]"');

  const result = await opencli('browser work state');
  expect(result).toContain('歡迎回來');
});
Playwright MCP + AI：自然語言驅動、AI 自動生成測試 
# Playwright MCP + AI Agent：自然語言驅動的測試
# 在 VS Code GitHub Copilot Chat 或 Claude Code 中：

# 「為 https://example.com/login 寫一個 Playwright 測試，
#   用 test@example.com / password123 登入，
#   驗證成功後能看到 '歡迎回來'」

# AI 通過 Playwright MCP 探索頁面後，自動生成：
import { test, expect } from '@playwright/test';

test('登入流程', async ({ page }) => {
  await page.goto('https://example.com/login');
  await page.locator('input[name="email"]').fill('test@example.com');
  await page.locator('input[name="password"]').fill('password123');
  await page.getByRole('button', { name: '登入' }).click();
  await expect(page.getByText('歡迎回來')).toBeVisible();
});

Playwright MCP 在 E2E 測試方面有明顯優勢：

  • AI 自動生成符合 Playwright Test 規範的 TypeScript 測試腳本
  • 搭配 Trace Viewer（時間旅行除錯），失敗時可回溯每一步 DOM 狀態
  • 搭配 Playwright Test MCP（獨立的測試版 MCP），啟動 Planner / Generator / Healer 等 AI Agents
  • 已內建於 GitHub Copilot Coding Agent，可自動驗證 PR 修改

OpenCLI 的 E2E 測試適合需要精確控制每個步驟、或已有 Vitest 測試架構的專案（詳見第 8–10 章）。

選型決策樹

選型決策樹 
你想要做什麼？
│
├── 操作特定平台（Twitter、GitHub、YouTube 等）？
│   └── 選 OpenCLI（有內建 Adapter）
│
├── 讓 AI Agent 完全自主地瀏覽、驗證網頁任務？
│   └── 選 Playwright MCP（AI 原生工具，無需手寫指令）
│
├── 撰寫 E2E 測試並自動維護？
│   └── 選 Playwright MCP（Trace Viewer + AI 自動生成測試）
│
├── 在 CI/CD 環境中無頭執行？
│   ├── 任意網站：選 Playwright MCP（--headless 即可）
│   └── 平台 API 操作：選 OpenCLI（CDP 模式）
│
├── 需要多 tab / 多任務並行隔離？
│   └── 選 OpenCLI（命名 Session 明確）
│
└── 混合使用：平台 Adapter + AI 驗證
    └── OpenCLI 做操作 + Playwright MCP 做 UI 驗證

搭配使用範例

OpenCLI 與 Playwright MCP 並不互斥，可以在同一工作流中各司其職：

混合工作流：OpenCLI 操作 + Playwright MCP 驗證 
#!/bin/bash
# 混合工作流：
# 1. OpenCLI 操作 Twitter（有 Adapter，語義清晰）
# 2. Playwright MCP 驗證發布結果（AI 確認 UI 狀態）

# Step 1：用 OpenCLI 發文（Adapter 處理所有 Twitter 細節）
opencli twitter post "今天用 OpenCLI 自動化了工作流程！ #DevTools"
echo "推文已送出"

# Step 2：在 Claude Code 中詢問 Playwright MCP 做 UI 驗證
# （claude mcp add playwright 後，在 Claude Code 對話框輸入）
# 「打開 twitter.com，確認最新推文包含 '今天用 OpenCLI'，截圖存為 tweet-verify.png」

本章小結

  • Playwright MCP 是 AI Agent 的原生工具：LLM 直接呼叫、無需子程序，最適合讓 AI 自主完成複雜的多步驟瀏覽器任務，以及搭配 Playwright Test 生成與維護 E2E 測試
  • OpenCLI 是人機協作的工具：語義指令清晰、平台 Adapter 豐富，適合有確定目標的自動化流程（尤其是特定平台），也更容易被人類閱讀和除錯
  • 兩者都基於 Accessibility Tree 概念（非截圖），都不需要視覺模型，但整合方式不同：OpenCLI 透過 CLI 命令，Playwright MCP 透過 MCP 工具呼叫
  • 在 AI Agent 工作流中，最佳策略往往是 混合使用：OpenCLI 的 Adapter 處理平台操作，Playwright MCP 負責 UI 驗證與自動化測試
