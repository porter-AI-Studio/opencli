第 12 章 · Part 4：AI 整合

在 Claude Code 中使用 OpenCLI

Claude Code 是 Anthropic 推出的 AI 編程助理 CLI，能在終端機對話中完成程式碼生成、重構、除錯等任務。OpenCLI 則讓使用者可以用指令行操控瀏覽器、抓取平台資料、自動化 Web 互動。

這兩個工具的結合，開啟了一種全新的工作模式：AI 不只是幫你寫程式碼，而是直接替你執行任務。

為什麼 Claude Code + OpenCLI 是絕配

單獨使用 Claude Code 時，AI 的能力邊界很清晰：它能生成程式碼、解釋概念、分析你貼入的文字資料，但它無法主動去「看」任何網頁，也無法幫你真正操作任何平台。你必須自己複製、貼上、截圖，再把資訊餵給 Claude。

加入 OpenCLI 之後，這個邊界消失了。Claude 可以透過 shell 指令直接呼叫 OpenCLI，取得即時的網頁資料，甚至操控瀏覽器完成互動操作，再把結果帶回對話繼續分析。

場景 沒有 OpenCLI 有 OpenCLI
研究新技術 手動搜尋、複製貼上給 Claude Claude 直接搜尋 GitHub、Reddit、Twitter 並彙整
操作 Web UI Claude 只能告訴你「點哪裡」 Claude 直接驅動瀏覽器完成操作
監控社群趨勢 訓練資料截止日後的資訊無從取得 即時抓取並分析最新討論
定期報告 需要人工每次準備資料 Claude 自動收集資料並生成報告

前置條件：本章範例假設你已安裝 Claude Code（npm install -g @anthropic-ai/claude-code）與 OpenCLI（npm install -g @jackwener/opencli），且 OpenCLI 已完成基本設定（瀏覽器連線或 adapter 配置）。

基礎整合：在 Claude Code session 中呼叫 OpenCLI

最直接的使用方式，是在 Claude Code 對話中直接輸入 opencli 指令。Claude Code 允許 AI 執行 shell 指令（取得你的授權後），並將輸出帶回對話脈絡繼續處理。

你不需要任何額外設定，只要開始對話就行。例如，你可以這樣說：

在 Claude Code 中直接使用 OpenCLI 
# 讓 Claude 幫你每週推薦值得學習的 TypeScript 專案
opencli github trending --language typescript --format json \
  | claude "從這些熱門 TypeScript repo 中，推薦 3 個最值得學習的，
    說明理由（技術棧、學習難度、實用性），並附上快速開始的建議。
    以繁體中文條列回答。"
分析 Twitter 當前趨勢 
# 分析當前技術趨勢中的 AI 相關話題
opencli twitter trends --format json \
  | claude "分析這些熱門話題，哪些與 AI 或軟體開發相關？
    對於技術人員來說，哪 3 個話題最值得關注？請說明原因。"

Claude 收到 OpenCLI 的 JSON 輸出後，能直接在對話中解析並給出有用的分析，整個流程不需要你手動複製任何資料。

管線（pipe）模式

你也可以在終端機直接用 pipe 把 OpenCLI 的輸出傳給 claude。這適合一次性的快速查詢，不需要開啟完整的對話 session：

Pipe 模式：單行指令直接分析 
# 將結果管線給 Claude 進行分析
opencli github search repos "Dify" --stars ">100" --format json --limit 10 \
  | claude "分析這些 repo 的 star 增長趨勢，找出最近 30 天活躍度最高的 3 個"

opencli twitter search "Dify AI" --limit 30 --format json \
  | claude "摘要這些推文的主要討論話題，以及社群對 Dify 的整體評價"

使用時機建議：簡單查詢用 pipe 模式快速取得結果；需要多輪互動、追問或迭代分析時，進入 Claude Code 完整 session 效果更好。

將 OpenCLI 設定為 Claude Code 工具

若你希望 Claude 在對話中能更主動地使用 OpenCLI（而不是每次都需要你說「去搜尋一下」），需要做兩件事：在 CLAUDE.md 中宣告可用工具，以及在 settings.json 中設定執行權限。

在 CLAUDE.md 宣告可用的 opencli 指令

CLAUDE.md 是 Claude Code 在每個 session 開始時都會讀取的說明文件，相當於告訴 Claude「你在這個專案中能用哪些工具、有哪些規則」。把 OpenCLI 可用的指令列在這裡，Claude 就會在需要時主動提議或執行：

CLAUDE.md — 宣告 OpenCLI 工具 
## 可用工具（OpenCLI）

以下工具已安裝並可直接在 shell 中執行，使用前請先確認 session 名稱。

- `opencli browser <session> state` — 讀取當前瀏覽器頁面狀態（DOM 摘要）
- `opencli browser <session> find <selector>` — 尋找頁面元素
- `opencli browser <session> click <ref>` — 點擊元素（使用 find 回傳的 ref）
- `opencli browser <session> type <ref> <text>` — 在輸入框輸入文字
- `opencli browser <session> nav <url>` — 導覽到指定 URL
- `opencli browser <session> screenshot` — 截圖目前頁面
- `opencli github trending [--language <lang>]` — 取得 GitHub 熱門 repo
- `opencli github search repos <query> [--stars <filter>]` — 搜尋 GitHub repo
- `opencli twitter search <query> [--limit <n>]` — 搜尋推文
- `opencli twitter trends` — 取得目前熱門話題
- `opencli reddit search <query> [--subreddit <r>]` — 搜尋 Reddit 貼文

### 輸出格式
加上 --format json 可輸出結構化 JSON，方便程式解析。
加上 --limit <n> 控制回傳筆數，避免塞爆 context。

在 settings.json 設定執行權限

Claude Code 預設在執行 shell 指令時會詢問確認。若你希望特定的 opencli 唯讀指令能自動執行（不需每次按 Enter 確認），可以在 .claude/settings.json 中加入允許規則：

.claude/settings.json — 允許自動執行 opencli 
// .claude/settings.json（專案層級）
{
  "permissions": {
    "allow": [
      "Bash(opencli:*)",
      "Bash(opencli browser *:*)",
      "Bash(opencli github *:*)",
      "Bash(opencli twitter *:*)",
      "Bash(opencli reddit *:*)"
    ]
  }
}

注意：只將唯讀操作（搜尋、取得趨勢、讀取頁面狀態）加入 allow list。寫入型操作（發文、按讚、填表單送出）應保持需要人工確認，避免 Claude 誤觸你不想執行的動作。

實戰場景一：AI 驅動的 Web 研究

這是最常見也最實用的整合場景。當你需要了解某個技術、產品或趨勢時，不再需要自己開瀏覽器逐一搜尋——直接告訴 Claude，讓它幫你同時搜尋多個平台並彙整報告。

以研究 Dify 這個 AI 平台為例，你在 Claude Code 中只需說：「幫我研究 Dify，搜尋 GitHub、Twitter、Reddit 的最新討論」，Claude 會依序執行以下操作：

合併多平台資料並產生研究報告 
# 合併多來源資料，產生完整報告
{
  echo "=== GitHub ==="
  opencli github search repos "Dify" --stars ">100" --format json --limit 5
  echo "=== Twitter ==="
  opencli twitter search "Dify AI" --limit 20 --format json
  echo "=== Reddit ==="
  opencli reddit search "Dify" --subreddit r/LocalLLaMA --limit 10 --format json
} | claude "請整合以上三個平台的資料，寫一份繁體中文研究報告，包含：
1. GitHub 上的開源生態現況
2. Twitter 社群討論熱度與主要聲音
3. Reddit 技術社群的實際使用心得
4. 綜合評估：Dify 的成熟度與值得關注的方向"

Claude 收到這些來自不同平台的 JSON 資料後，會整合成一份有條理的報告，包含各平台的側重點差異——GitHub 反映開發者生態、Twitter 反映輿論聲量、Reddit 反映實際使用者的深度評價。

提示：在 prompt 中明確指定輸出語言和格式（例如「以繁體中文，條列式說明」），能讓 Claude 的回答更符合你的使用需求，減少二次整理的時間。

實戰場景二：AI 驅動的瀏覽器操作

OpenCLI 的瀏覽器指令讓 Claude 能「看到」頁面並做出決策。關鍵在於 state 指令——它會回傳頁面上所有可互動元素的結構化清單，Claude 可以用這份清單來決定下一步要點哪個元素、要在哪個輸入框填入資料。

Claude 如何理解頁面

讀取頁面狀態的工作原理 
# Claude 讀取頁面狀態的互動範例
# 在 Claude Code 中，你可以直接說：
# "幫我讀取 https://example.com 的頁面結構"

# Claude 會自動執行：
opencli browser main nav "https://example.com"
opencli browser main state

# state 指令回傳類似這樣的結構化輸出：
# {
#   "url": "https://example.com",
#   "title": "Example Domain",
#   "elements": [
#     { "ref": "e1", "tag": "h1", "text": "Example Domain" },
#     { "ref": "e2", "tag": "p", "text": "This domain is for use..." },
#     { "ref": "e3", "tag": "a", "text": "More information...", "href": "https://iana.org/..." }
#   ]
# }

state 指令的輸出中，每個元素都有一個唯一的 ref 編號。Claude 會根據元素的標籤、文字、屬性來判斷這是什麼元素，然後用 ref 來精確指定後續操作的目標。

完整互動流程：登入並截圖

以下是 Claude 驅動瀏覽器完成登入操作的完整步驟。每一步都先讀取當前頁面狀態，再根據狀態決定下一個動作：

Claude 驅動的完整登入流程 
# 完整互動流程：Claude 驅動登入並截圖

# Step 1：Claude 導覽到登入頁
opencli browser work nav "https://app.example.com/login"

# Step 2：讀取頁面找到輸入框
opencli browser work state

# Step 3：Claude 根據 state 輸出，找到 email 欄位的 ref
opencli browser work find "input[type=email]"
# 回傳：{ "ref": "e5", "tag": "input", "type": "email" }

# Step 4：填入帳號密碼
opencli browser work type e5 "user@example.com"
opencli browser work find "input[type=password]"
# 回傳：{ "ref": "e6", "tag": "input", "type": "password" }
opencli browser work type e6 "mysecretpassword"

# Step 5：點擊登入按鈕
opencli browser work find "button[type=submit]"
# 回傳：{ "ref": "e7", "tag": "button", "text": "登入" }
opencli browser work click e7

# Step 6：等待跳轉後截圖確認
opencli browser work screenshot

整個流程中，Claude 的角色是「根據頁面狀態做出決策的 agent」。它不是盲目地執行固定腳本，而是每一步都先讀取當前狀態，再決定下一個動作。這讓它能適應頁面結構的細微變化，比傳統的 Selenium 腳本更有彈性。

session 名稱：上面範例使用 work 作為 session 名稱，你可以在 Claude Code 對話開始時告訴 Claude 要使用哪個 session，或是在 CLAUDE.md 中定義各 session 的用途與使用限制。

透過 Skills 封裝常用流程

如果某個 OpenCLI 操作序列是你經常執行的，可以把它封裝成 Claude Code Skill——一個描述「遇到這個指令時要做什麼」的 Markdown 文件。一旦封裝好，只需輸入 /skill-name 關鍵字，Claude 就會自動走完整個流程。

撰寫 Skill 檔案

Skill 檔案放在 .claude/skills/ 目錄下，以 .md 副檔名儲存。內容包含指令描述、參數說明，以及 Claude 應該依序執行的步驟：

.claude/skills/twitter-report.md 
# .claude/skills/twitter-report.md
# 這個 skill 讓你輸入 /twitter-report <關鍵字> 就能自動產生分析報告

## 描述
搜尋 Twitter 上關於指定關鍵字的討論，彙整成結構化報告。

## 用法
/twitter-report <關鍵字> [--limit <n>]

## 步驟

1. 使用 opencli 搜尋推文：
```bash
opencli twitter search "$ARGS" --limit 30 --format json
```

2. 分析結果，依以下格式輸出報告：
   - **摘要**：3 句話說明主要討論方向
   - **正面觀點**：列出 3 條具代表性的正面推文（附作者）
   - **負面觀點**：列出 3 條批評或質疑（附作者）
   - **關鍵意見領袖**：列出討論中出現的重要帳號
   - **結論**：一段綜合評估

3. 最後詢問使用者是否要進一步搜尋相關話題。

在 CLAUDE.md 中引入 Skill

在 CLAUDE.md 中列出所有可用的 Skill，讓 Claude 知道遇到對應指令時該做什麼：

CLAUDE.md — 引入 Skills 與工具定義 
# CLAUDE.md（專案根目錄）

# 通用規則
@.claude/rules/core.md

## 可用 Skills
- `/twitter-report` — 搜尋並分析 Twitter 討論，見 .claude/skills/twitter-report.md
- `/github-scan` — 掃描 GitHub 熱門 repo 並推薦，見 .claude/skills/github-scan.md
- `/web-research` — 跨平台研究報告，見 .claude/skills/web-research.md

## 可用工具（OpenCLI）
- `opencli browser <session> <command>` — 控制瀏覽器
- `opencli twitter search <query>` — 搜尋推文
- `opencli twitter trends` — 取得熱門話題
- `opencli github trending` — 取得 GitHub 熱門
- `opencli github search repos <query>` — 搜尋 GitHub repo
- `opencli reddit search <query>` — 搜尋 Reddit 貼文

設定完成後，你在 Claude Code 中輸入 /twitter-report Dify，Claude 就會自動執行對應的 opencli 搜尋指令、分析結果並輸出格式化報告，整個過程不需要你重複說明步驟。

Skill 設計原則：每個 Skill 聚焦單一任務，步驟描述越具體越好。避免在一個 Skill 裡放太多不相關的邏輯，否則 Claude 容易漏掉某些步驟。

注意事項與最佳實踐

1. 寫入與互動操作必須先確認

搜尋、瀏覽、截圖這類唯讀操作讓 Claude 自動執行是安全的。但任何會改變資料或狀態的操作——發推文、按讚、填表單、點擊購買按鈕——都應該讓 Claude 先描述「它打算做什麼」，由你確認後再執行：

區分唯讀操作與寫入操作 
# 高風險操作：需要人工確認後才能執行

# 發推文（寫入操作）—— 絕對不要讓 Claude 自動執行
# opencli twitter post "剛讀了一篇很棒的文章 #AI"
# 除非使用者明確確認，否則只能「建議」這個指令，不直接執行

# 按讚 / 追蹤 / 轉推（互動操作）
# opencli twitter like <tweet_id>
# opencli twitter follow <username>

# 填表單並送出
# opencli browser main click submit-btn  # 如果是購買或申請表單，務必先截圖確認

# 安全做法：先截圖，讓使用者確認後再執行
opencli browser main screenshot
# "這是目前的表單狀態，確認要送出嗎？"

2. 善用 --format json 提升解析品質

Claude 解析結構化 JSON 的準確率遠高於純文字輸出。任何需要 Claude 進一步分析的 opencli 指令，都應加上 --format json：

推薦的輸出格式設定 
# 不推薦：純文字輸出，Claude 難以解析
opencli github trending

# 推薦：JSON 輸出，結構清晰
opencli github trending --format json

# 搭配 limit 控制資料量
opencli twitter search "AI agent" --format json --limit 20

# 多欄位過濾（若 adapter 支援）
opencli github search repos "langchain" \
  --stars ">500" \
  --language python \
  --format json \
  --limit 10

3. 用 --limit 控制 context 用量

Claude 的 context 視窗是有限的。如果一次抓取幾百筆資料塞進對話，不僅浪費 token，也可能讓 Claude 無法有效處理後半段的資料。建議依任務需求設定合理的 --limit：

  • 趨勢分析、概覽性任務：--limit 20 到 --limit 30 通常已足夠
  • 需要廣度的研究：可分批執行，每批 --limit 50，讓 Claude 逐批摘要後再合併
  • 即時監控：--limit 10 快速取得最新動態，適合頻繁執行的場景

4. 敏感 session 要謹慎授權

已登入帳號的瀏覽器 session 擁有你的身份憑證，授權給 Claude 自動操作時需格外謹慎。建議用命名規範區分公開與敏感 session，並在 settings.json 只允許自動執行公開 session 的操作：

區分敏感與公開 session 的授權設定 
// .claude/settings.json — 區分敏感與公開 session 的授權設定

// session 命名慣例：
// "main" / "public"：未登入的公開瀏覽
// "work" / "logged-in"：已登入帳號的操作

{
  "permissions": {
    "allow": [
      "Bash(opencli browser main *:*)",
      "Bash(opencli github *:*)",
      "Bash(opencli twitter search *:*)"
      // 注意：不加 "Bash(opencli browser work *:*)"
      // work session 含登入憑證，所有操作保持逐次確認
    ]
  }
}

小結

Claude Code 與 OpenCLI 的整合，代表著 AI 助理從「提供建議」進化到「直接執行」的重要一步。透過本章介紹的幾個關鍵設定：

  1. 在 CLAUDE.md 中宣告可用的 OpenCLI 工具，讓 Claude 知道有這些能力
  2. 在 settings.json 中設定唯讀操作的自動執行權限，減少不必要的確認中斷
  3. 用 --format json 和 --limit 確保輸出品質與 context 效率
  4. 把常用流程封裝成 Skill，讓重複任務一個指令就能完成
  5. 寫入與互動操作保持人工確認，避免 AI 誤觸敏感動作

掌握這些原則，你就能打造出一個真正能替你「做事」的 AI 工作流程，而不只是一個回答問題的助理。
