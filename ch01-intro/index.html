第 1 章 · Part 1：入門

什麼是 OpenCLI？

瀏覽器自動化的新範式——讓 AI Agent 能像人類一樣操作網頁，零程式碼、零憑證、即時執行。

為什麼需要 OpenCLI？

傳統的瀏覽器自動化工具（如 Selenium、Playwright）需要你寫程式碼、維護測試腳本、處理複雜的選擇器。 當你想讓 AI Agent 自動操作網頁時，這些工具的學習曲線和維護成本往往成為最大瓶頸。

OpenCLI 改變了這個局面。它的核心理念是：語言即是最強的操作介面。 你只需要用自然語言描述你想做的事，或是用簡單的指令組合，就能完成複雜的網頁自動化。

OpenCLI 的核心特色

零憑證操作（Zero-Credential）

OpenCLI 直接連接你已登入的瀏覽器，無需提供帳號密碼。它透過 Browser Bridge Extension 與真實的 Chrome 瀏覽器溝通，利用你現有的登入狀態操作各平台。

💡
安全優勢

你的帳號密碼永遠只存在瀏覽器裡，OpenCLI 不會要求你提供任何憑證。這讓自動化腳本可以安全地分享，不用擔心洩漏敏感資訊。

AI Agent 優先設計

OpenCLI 從一開始就為 AI Agent 設計。每個指令都有結構化的輸出，可以直接被 Claude、GPT 等 AI 解析和使用。 AI 可以根據頁面狀態動態決定下一步操作，實現真正的智能自動化。

80+ 平台原生適配器

OpenCLI 內建超過 80 個平台的專屬適配器，包含 Twitter/X、YouTube、GitHub、Reddit、LinkedIn、Bilibili、知乎等主流平台。 這些適配器針對各平台的特性進行優化，提供更穩定、更高效的操作體驗。

三層架構設計

OpenCLI 由三個核心組件協同工作：

CLI 層

使用者介面，接受指令輸入，回傳結構化結果。支援管道操作（pipe）和腳本組合。

Daemon 層

後台常駐服務，管理 Session 生命週期，維護瀏覽器連線狀態，處理並發請求。

Extension 層

Browser Bridge Chrome Extension，作為 CLI 與瀏覽器之間的橋梁，使用 CDP 協定通訊。

使用者 / AI Agent
      ↓
  opencli CLI
      ↓ (HTTP / WebSocket)
  opencli daemon
      ↓ (CDP / WebSocket)
Browser Bridge Extension
      ↓
  Chrome 瀏覽器

OpenCLI vs 傳統工具

為什麼選擇 OpenCLI 而非 Playwright 或 Selenium？

特性 OpenCLI Playwright Selenium
需要寫程式碼 ❌ 不需要 ✅ 需要 ✅ 需要
AI Agent 整合 ✅ 原生支援 ⚠️ 需要包裝 ⚠️ 需要包裝
使用真實瀏覽器登入狀態 ✅ 原生支援 ⚠️ 需要設定 ⚠️ 需要設定
平台專屬適配器 ✅ 80+ 平台 ❌ 無 ❌ 無
學習曲線 低（命令列） 高（程式語言） 高（程式語言）
CI/CD 整合 ✅ CDP 模式 ✅ 原生支援 ✅ 原生支援
ℹ️
互補而非取代

OpenCLI 並非要取代 Playwright。對於需要精細控制的 E2E 測試，Playwright 仍是首選。OpenCLI 的強項在於快速原型開發、AI Agent 整合，以及需要利用真實登入狀態的自動化場景。

典型使用場景

社群媒體自動化

範例：抓取 Twitter 趨勢 
# 取得今日熱門話題
opencli twitter trends

# 搜尋特定關鍵字的推文
opencli twitter search "AI Agent" --limit 20 --format json

AI Agent 工作流

範例：在 Claude Code 中使用 
# 讓 Claude 幫你分析 GitHub 趨勢
opencli github trending --language typescript | claude "分析這些專案，找出共同趨勢"

# 自動截圖並分析
opencli browser work screenshot --full-page | claude "描述這個頁面的主要內容"

網頁資料擷取

範例：結構化資料擷取 
# 擷取電商商品資訊
opencli browser navigate "https://example.com/products"
opencli browser extract --selector ".product-card" --fields "name,price,rating"

# 監控頁面變化
opencli browser wait --text "庫存已補充" --timeout 30000

E2E 測試輔助

範例：配合 Vitest 做 E2E 測試 
# 在測試中使用 OpenCLI
import { exec } from 'child_process'

test('登入流程', async () => {
  await exec('opencli browser work navigate "https://app.example.com/login"')
  await exec('opencli browser work type "#username" "testuser"')
  await exec('opencli browser work click "#login-btn"')
  await exec('opencli browser work wait --text "歡迎回來"')
})
