第 7 章 · Part 2：瀏覽器自動化

進階操作（eval、wait、network）

掌握基本的點擊與填寫之後，真正複雜的自動化任務需要更強大的工具：直接執行 JavaScript 操作 DOM、 精確等待非同步事件、攔截網路請求驗證 API 行為。本章深入講解這些進階指令，並以完整的 Chatbot 互動流程 示範如何將它們組合成可靠的自動化腳本。

eval：在頁面執行 JavaScript

eval 指令讓你在目標頁面的 JavaScript 執行環境中直接執行程式碼，可以讀取 DOM 狀態、 操作元素，甚至存取 localStorage。這是當標準指令（click、fill…）無法滿足需求時的終極手段。

基本語法

eval 基本語法 
opencli browser <session> eval "<javascript>"
🚫
重大限制：eval 只接受單行 JavaScript

Multi-line JS 經由 shell 傳給 opencli 時，會觸發 Unexpected token ')' parse error。所有 JS 必須寫成單行——無論邏輯多複雜，都需要壓縮成一行，不能使用換行字元。

單行 vs 多行：正確與錯誤示範 
# ✅ 單行 - 正確
opencli browser work eval "document.title"
opencli browser work eval "document.querySelectorAll('.message.bot').length"
opencli browser work eval "Array.from(document.querySelectorAll('.item')).map(el => el.textContent).join(',')"

# ❌ 多行 - 會報 Unexpected token ')' 錯誤
opencli browser work eval "(() => {
  const els = document.querySelectorAll('.msg');
  return els.length;
})()"

常見 eval 用法

eval 實用範例集 
# 取得元素數量
opencli browser work eval "document.querySelectorAll('.message.bot').length"

# 取得頁面標題
opencli browser work eval "document.title"

# 取得輸入框目前內容
opencli browser work eval "document.querySelector('#search-input').value"

# 取得頁面所有可見文字
opencli browser work eval "document.body.innerText"

# 確認元素是否存在（回傳 true / false）
opencli browser work eval "!!document.querySelector('.success-banner')"

# 觸發點擊（適用於普通 click 指令無法作用的元素）
opencli browser work eval "document.querySelector('.special-btn').click()"

# 滾動到頁面底部
opencli browser work eval "window.scrollTo(0, document.body.scrollHeight)"

# 讀取 localStorage 值
opencli browser work eval "localStorage.getItem('user-token')"

在 TypeScript Helper 中封裝 eval

直接在程式碼中呼叫 eval 時，建議封裝成 helper function，自動處理 JSON parse 與型別轉換， 讓呼叫端的程式碼更簡潔。

evalJs helper 函式 
export async function evalJs(js: string) {
  const r = must(await browser('eval', js));
  try {
    return JSON.parse(r.stdout);
  } catch {
    return r.stdout.trim();
  }
}

// 使用範例：搭配型別轉換
const count   = Number(await evalJs(`document.querySelectorAll('.message.bot').length`));
const title   = String(await evalJs(`document.title`));
const hasError = Boolean(await evalJs(`!!document.querySelector('.error-msg')`));
const token   = String(await evalJs(`localStorage.getItem('auth-token')`));
💡
Template Literal 是安全的單行寫法

在 TypeScript 中使用 template literal（反引號）傳入 JS 字串時，字串本身仍然是單一個值，不會有換行問題。但要注意：字串內容本身不能包含換行，只能是邏輯上的一行 JS 運算式。

wait：精確等待非同步事件

現代 Web 應用大量使用非同步載入。如果在元素還沒出現、API 還沒回應時就執行下一步， 自動化腳本必然失敗。wait 指令提供三種等待模式，對應不同的等待需求。

模式一：wait selector — 等待 CSS 元素出現

wait selector 用法 
# 等待特定 CSS 選擇器對應的元素出現
opencli browser work wait selector ".reply-message" --timeout 30000
opencli browser work wait selector "#success-notification" --timeout 10000

# 等待按鈕從 disabled 恢復可點擊
opencli browser work wait selector "button:not([disabled])" --timeout 15000

# 等待對話框出現
opencli browser work wait selector "[role='dialog']" --timeout 8000

模式二：wait text — 等待特定文字出現

wait text 用法 
# 等待成功訊息
opencli browser work wait text "登入成功" --timeout 10000

# 等待長時間處理完成
opencli browser work wait text "處理完成" --timeout 60000

# 等待錯誤訊息（用於驗證錯誤處理）
opencli browser work wait text "帳號或密碼錯誤" --timeout 5000

# 等待特定狀態文字
opencli browser work wait text "404 Not Found" --timeout 5000

模式三：wait xhr — 等待 API 請求完成

wait xhr 監聽瀏覽器的 XMLHttpRequest 與 Fetch 網路請求， 等待 URL 中包含指定字串的請求完成。這是處理 Streaming 回應、非同步 API 呼叫最可靠的方式。

wait xhr 用法 
# 等待包含 /api/chat 路徑的 XHR 請求完成
opencli browser work wait xhr "/api/chat" --timeout 30000

# 等待訊息 API
opencli browser work wait xhr "/api/messages" --timeout 15000

# 等待上傳完成
opencli browser work wait xhr "/upload" --timeout 120000

三種等待模式比較

等待類型 用途 最適合的場景
wait selector CSS 元素出現 新元素動態載入後需要操作
wait text 特定文字出現 確認操作成功 / 偵測錯誤訊息
wait xhr API 請求完成 Streaming 回應、非同步資料載入

手動 Polling：當 wait 指令不夠用時

某些情境下（例如等待 Streaming Chatbot 的回覆穩定下來）， 內建的 wait 指令無法判斷「回覆是否真的結束」。 這時可以用 eval 搭配手動 polling 邏輯來實作更細膩的等待策略。

等待 Streaming Chatbot 回覆完成 
/**
 * 等待 streaming chatbot 回覆完成。
 * 偵測策略：bot 訊息數量增加後，頁面文字長度連續 4 秒不再變化，視為回覆完成。
 */
async function waitReplyComplete(startCount: number, timeoutMs = 90_000): Promise<string> {
  const t0 = Date.now();
  let lastLen = -1;
  let stableSince = Date.now();
  let seen = false;

  while (Date.now() - t0 < timeoutMs) {
    const count = Number(await evalJs(
      `document.querySelectorAll('.message.bot').length`
    ));
    if (count > startCount) seen = true;

    const text = String(await evalJs(`document.body.innerText`));

    if (text.length === lastLen && seen && Date.now() - stableSince >= 4000) {
      return text;  // 穩定超過 4 秒，視為完成
    }
    if (text.length !== lastLen) {
      lastLen = text.length;
      stableSince = Date.now();  // 重設穩定計時
    }

    await new Promise(r => setTimeout(r, 1000));
  }

  throw new Error(`reply timed out after ${timeoutMs}ms`);
}
為什麼不直接用 wait xhr？
Streaming API 的 XHR 請求雖然在第一個 chunk 送達時就算「完成」，但 bot 還在持續輸出文字。waitReplyComplete 透過觀察 DOM 文字長度的穩定性，才能真正確認輸出結束。

network：監聽網路請求

network 指令讀取瀏覽器在目前 session 中記錄的網路請求， 輸出 JSON 格式的請求清單。這讓你可以驗證 API 呼叫是否正確發出、 檢查 request/response 內容，或確認 HTTP status code。

network 基本用法 
# 列出所有網路請求
opencli browser work network

輸出的 JSON 陣列，每筆記錄包含以下欄位：

network 輸出結構範例 
[
  {
    "url": "https://app.example.com/api/chat",
    "method": "POST",
    "status": 200,
    "requestHeaders": { "Content-Type": "application/json" },
    "responseHeaders": { "Content-Type": "application/json" },
    "requestBody": "{\"message\":\"Hello\"}",
    "responseBody": "{\"reply\":\"Hi there!\"}"
  }
]

過濾特定請求

搭配 jq 過濾網路記錄 
# 只看 API 請求
opencli browser work network | jq '[.[] | select(.url | contains("/api/"))]'

# 只看 POST 請求
opencli browser work network | jq '[.[] | select(.method == "POST")]'

# 找特定狀態碼
opencli browser work network | jq '[.[] | select(.status >= 400)]'

# 只取 URL 列表
opencli browser work network | jq '[.[].url]'

在測試中驗證 API 行為

測試中讀取並驗證網路請求 
// 執行使用者動作
await fill('textarea', '測試問題');
await keys('Enter');

// 等待 API 呼叫完成
await browser('wait', 'xhr', '/api/chat', '--timeout', '30000');

// 取得網路記錄並解析
const networkResult = must(await browser('network'));
const requests: NetworkEntry[] = JSON.parse(networkResult.stdout);

// 找到 chat API 請求
const chatReq = requests.find(r => r.url.includes('/api/chat'));
expect(chatReq).toBeDefined();
expect(chatReq?.method).toBe('POST');
expect(chatReq?.status).toBe(200);

// 驗證 request body 內容
const body = JSON.parse(chatReq?.requestBody ?? '{}');
expect(body.message).toBe('測試問題');
⚠️
network 的時機陷阱

network 指令讀取的是「到目前為止」的請求記錄。如果你在觸發動作之前就執行 network，可能看不到預期的請求。正確流程是：先觸發操作 → wait xhr 等待完成 → 再執行 network 讀取結果。

screenshot：截圖記錄

截圖是自動化測試中最重要的 debug 工具。在每個關鍵步驟截圖，失敗時能立刻看到瀏覽器的實際狀態， 大幅縮短排錯時間。

screenshot 用法 
# 截取目前視窗狀態
opencli browser work screenshot output.png

# 截取到指定路徑（目錄需事先存在）
opencli browser work screenshot artifacts/step1.png

# 全頁截圖
opencli browser work screenshot --full-page artifacts/full.png

測試中的截圖最佳實踐

測試 helper：截圖 + 失敗自動截圖 
import { afterEach } from 'vitest';

// 快速截圖 helper
async function snap(name: string) {
  await browser('screenshot', `artifacts/${name}-${Date.now()}.png`);
}

// 測試失敗時自動截圖，保留現場
afterEach(async (ctx) => {
  if (ctx.task.result?.state === 'fail') {
    await snap(`FAILED-${ctx.task.name.replace(/\s+/g, '_')}`);
  }
});

// 在測試步驟中手動截圖
test('使用者登入流程', async () => {
  await browser('open', 'http://localhost:3000/login');
  await snap('01-login-page');

  await fill('#email', 'user@example.com');
  await fill('#password', 'secret');
  await snap('02-filled-form');

  await click('button[type="submit"]');
  await browser('wait', 'text', '登入成功', '--timeout', '10000');
  await snap('03-after-login');
});

extract：擷取頁面為 Markdown

extract 指令將目前頁面的主要內容轉換為 Markdown 格式輸出， 過濾掉導覽列、廣告等雜訊，保留核心文章或資料結構。 特別適合搭配 AI 工具做進一步分析。

extract 用法 
# 擷取頁面主要內容（輸出 Markdown）
opencli browser work extract

# 直接管道給 AI 分析
opencli browser work extract | claude "請摘要這篇文章的三個重點"

# 儲存到檔案
opencli browser work extract > page-content.md
💡
extract vs eval("document.body.innerText")

extract 會智慧過濾頁面結構，輸出乾淨的 Markdown；eval("document.body.innerText") 則回傳原始純文字，包含所有導覽、頁尾等雜訊。需要給人或 AI 閱讀的內容用 extract；需要精確擷取特定元素值時用 eval。

組合技：Chatbot 完整互動流程

把本章所有指令組合起來，以下是一個完整的 Chatbot 互動自動化腳本， 涵蓋頁面開啟、狀態確認、填寫送出、等待回應、截圖記錄、擷取結果的完整流程。

Shell Script 版本

Chatbot 完整互動流程（Bash） 
#!/bin/bash
SESSION="chat"

# 1. 開啟聊天頁面
opencli browser $SESSION open http://localhost:8090

# 2. 等待輸入框出現，確認頁面已就緒
opencli browser $SESSION wait selector "textarea" --timeout 10000

# 3. 截圖記錄初始狀態
opencli browser $SESSION screenshot artifacts/01-initial.png

# 4. 記錄目前的 bot 訊息數量（作為 baseline）
BEFORE=$(opencli browser $SESSION eval "document.querySelectorAll('.message.bot').length")
echo "Bot messages before: $BEFORE"

# 5. 填寫問題並送出
opencli browser $SESSION fill "textarea" "你好，請介紹一下你自己"
opencli browser $SESSION keys "Enter"

# 6. 等待 XHR API 請求完成
opencli browser $SESSION wait xhr "/api/chat" --timeout 30000

# 7. 截圖記錄回覆狀態
opencli browser $SESSION screenshot artifacts/02-after-reply.png

# 8. 擷取最新一則 bot 回覆的文字
REPLY=$(opencli browser $SESSION eval "document.querySelector('.message.bot:last-child').innerText")
echo "Bot reply: $REPLY"

# 9. 驗證網路請求狀態
opencli browser $SESSION network | jq '[.[] | select(.url | contains("/api/chat"))] | .[0].status'

TypeScript / Vitest 版本

Chatbot 完整互動流程（TypeScript） 
import { test, expect, afterEach } from 'vitest';
import { browser, must, fill, keys } from './helpers';

async function snap(name: string) {
  await browser('screenshot', `artifacts/${name}-${Date.now()}.png`);
}

async function evalJs(js: string) {
  const r = must(await browser('eval', js));
  try { return JSON.parse(r.stdout); } catch { return r.stdout.trim(); }
}

afterEach(async (ctx) => {
  if (ctx.task.result?.state === 'fail') {
    await snap(`FAILED-${ctx.task.name.replace(/\s+/g, '_')}`);
  }
});

test('chatbot 能正確回覆問題', async () => {
  // 1. 開啟頁面並等待就緒
  await browser('open', 'http://localhost:8090');
  await browser('wait', 'selector', 'textarea', '--timeout', '10000');
  await snap('01-initial');

  // 2. 記錄初始 bot 訊息數
  const before = Number(await evalJs(`document.querySelectorAll('.message.bot').length`));

  // 3. 填寫並送出問題
  await fill('textarea', '你好，請介紹一下你自己');
  await keys('Enter');

  // 4. 等待 API 完成
  await browser('wait', 'xhr', '/api/chat', '--timeout', '30000');
  await snap('02-reply');

  // 5. 確認新增了一則 bot 回覆
  const after = Number(await evalJs(`document.querySelectorAll('.message.bot').length`));
  expect(after).toBeGreaterThan(before);

  // 6. 取得回覆內容並驗證非空
  const reply = String(await evalJs(`document.querySelector('.message.bot:last-child').innerText`));
  expect(reply.length).toBeGreaterThan(0);

  // 7. 驗證 API 請求狀態碼為 200
  const netResult = must(await browser('network'));
  const requests = JSON.parse(netResult.stdout);
  const chatReq = requests.find((r: any) => r.url.includes('/api/chat'));
  expect(chatReq?.status).toBe(200);
}, 60_000);

疑難排解

症狀 可能原因 解法
Unexpected token ')' in eval JS 字串包含換行（多行） 將 JS 改寫成單行運算式
wait selector timeout 選擇器不正確，或元素從未出現 先用 state 指令或截圖確認選擇器；考慮用 wait text 替代
network 回傳空陣列 [] 在觸發動作前就執行了 network 先觸發動作 → wait xhr → 再執行 network
screenshot 畫面全黑 頁面尚未載入完成 在截圖前加 wait selector 確認頁面主要元素已出現
eval 回傳 null 或 undefined querySelector 找不到元素 先用 !!document.querySelector(...) 確認元素存在
wait xhr 比預期早結束 Streaming API 第一個 chunk 即算完成 改用手動 polling（waitReplyComplete）等文字穩定
💡
Debug 三步驟

遇到自動化腳本失敗時，建議按此順序排查：1. 查看截圖（artifacts/ 目錄）確認瀏覽器實際狀態；2. 執行 state 指令取得目前 DOM 結構；3. 用 eval 逐步確認元素是否存在與值是否正確。

本章小結

本章涵蓋了 OpenCLI 進階操作的核心指令：

  • eval：執行 JavaScript 讀取 DOM 狀態，記住必須單行
  • wait selector / text / xhr：三種等待模式對應不同的非同步場景
  • network：讀取並驗證 API 請求記錄，搭配 jq 過濾更靈活
  • screenshot：關鍵步驟截圖，失敗自動截圖，是最有效的 debug 工具
  • extract：將頁面內容轉為 Markdown，適合搭配 AI 分析

這些指令的真正威力在於組合使用：用 eval 讀取狀態、用 wait 精確等待、用 network 驗證 API、 用 screenshot 留下記錄，構成一個完整且可靠的自動化測試循環。
