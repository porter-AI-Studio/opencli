第 13 章 · Part 4：AI 整合

Skills 安裝與管理

Skills 是 Claude Code 的超能力核心——一個 Skill 就是一份描述工作流程的 Markdown 檔案， 讓 Claude 知道在特定情境下該執行哪些步驟、呼叫哪些工具。 結合 OpenCLI，Skills 能將複雜的網頁自動化任務封裝成一行觸發指令， 可重複執行、可版本控制、可與團隊共享。

1. 什麼是 Skills

在 Claude Code 的架構中，Skill 是一個儲存在 .md 檔案裡的工作流程描述。 當你在對話中輸入觸發指令（如 /twitter-report），Claude 會讀取對應的 Skill 檔案， 依照步驟說明逐一執行，包括呼叫 OpenCLI 指令、處理輸出、產生報告。

比較項目 一般 Claude 對話 Skill
執行方式 每次手動描述需求 一行觸發指令
一致性 每次結果可能不同 標準化流程，輸出格式固定
可重複性 低（依賴對話上下文） 高（獨立執行，無需上下文）
共享性 無法直接分享 一個 .md 檔案即可分享
版本控制 無 可加入 git 管理

OpenCLI Skill 的特殊之處在於：步驟說明中包含具體的 opencli 指令， 讓 Claude 能直接操控瀏覽器、呼叫各平台 adapter，完成資料抓取、互動、報告產生等完整流程， 而不只是文字生成。

一句話定義：Skill = 觸發條件 + 步驟說明 + OpenCLI 工具調用指令。 你把重複性的自動化工作寫成一份 Skill，之後只要一行指令，Claude 就能獨立完成整個流程。

2. Skill 檔案結構

Skill 檔案是標準 Markdown，搭配 YAML frontmatter 描述 metadata。 以下是一個完整的範例，涵蓋所有常用欄位：

twitter-report.md — 完整 Skill 範例 
---
name: twitter-report
description: 搜尋 Twitter 趨勢並產生分析報告
trigger: /twitter-report
---

# Twitter 趨勢報告

## 前置需求
- 已執行 `opencli twitter auth` 完成登入
- 已安裝 Twitter adapter：`opencli adapter install twitter`

## 參數
- `topic`（可選）：指定搜尋主題，預設搜尋當前熱門趨勢

## 步驟
1. 執行 `opencli twitter trends --limit 20 --format json` 取得目前趨勢清單
2. 執行 `opencli twitter search "${topic}" --limit 50 --format json` 搜尋相關推文
3. 分析結果，找出與 AI／技術相關的話題
4. 整理熱門度、互動數、關鍵人物資訊
5. 產生 Markdown 格式報告，包含摘要、熱門推文、趨勢圖

## 輸出格式
產生一份 Markdown 報告，儲存為 `twitter-report-YYYY-MM-DD.md`，包含：
- 執行摘要（3-5 句話）
- 熱門話題 Top 10 表格
- 值得關注的推文（附連結）
- 建議行動項目

Frontmatter 各欄位說明：

  • name：Skill 的唯一識別名稱，建議使用 kebab-case
  • description：一句話說明這個 Skill 做什麼，會顯示在 Claude 的工具列表中
  • trigger：觸發指令，以 / 開頭，使用者輸入此指令時啟動 Skill

正文部分建議包含以下段落（非強制，但強烈推薦）：

  • 前置需求：哪些 adapter 需要先登入？需要特殊權限嗎？
  • 參數：Skill 接受哪些輸入？預設值是什麼？
  • 步驟：詳細的執行流程，包含具體的 opencli 指令
  • 輸出格式：最終產出物的格式、儲存位置

步驟寫得越具體越好。直接寫出完整的 opencli 指令， 包含 --format json、--limit 等參數， Claude 才能準確執行，不會因為解讀模糊而產生變體行為。

3. Skills 的存放位置

Claude Code 會從兩個位置載入 Skills，優先順序由下而上（專案層級覆蓋全域）：

層級 路徑 作用範圍 適合放什麼
全域 ~/.claude/skills/ 所有專案 通用工具、個人常用 workflow
專案 .claude/skills/ 僅此專案 專案特定流程、團隊共享 workflow

Skills 需要透過 CLAUDE.md 顯式引入才會生效。 Claude Code 不會自動掃描所有 .md 檔案， 你必須在 CLAUDE.md 中用 @ 語法告訴 Claude 哪些 Skills 可用：

CLAUDE.md — 引入 Skills 範例 
# CLAUDE.md 引入範例

## 全域 Skills
@~/.claude/skills/github-digest.md
@~/.claude/skills/opencli-pack/twitter-report.md

## 專案 Skills（相對路徑）
@.claude/skills/deploy-check.md
@.claude/skills/weekly-report.md

引入即生效。只要在 CLAUDE.md 中加入 @path/to/skill.md， Claude 在所有對話中都能使用該 Skill。 請確認引入的 Skill 內容安全可信，特別是從第三方來源下載的 Skill。

4. 安裝社群 Skills

社群貢獻者和官方套件提供了許多現成的 Skills，可以直接下載使用。 安裝流程分三步：下載、檢查、引入。

下載社群 Skills 到全域目錄 
# 下載單一 skill 到全域目錄
curl -o ~/.claude/skills/github-digest.md \
  https://raw.githubusercontent.com/user/opencli-skills/main/github-digest.md

# 使用 git clone 安裝整套 skill 包
git clone https://github.com/user/opencli-skills ~/.claude/skills/opencli-pack

# 安裝後確認內容（安全第一，先看再用）
cat ~/.claude/skills/github-digest.md
在專案中建立並使用 Skills 
# 建立專案層級 skill 目錄（只對此專案生效）
mkdir -p .claude/skills

# 在 CLAUDE.md 中引入專案 skill
echo "@.claude/skills/my-skill.md" >> CLAUDE.md

# 引入全域 skill
echo "@~/.claude/skills/github-digest.md" >> CLAUDE.md

安全原則：先看後用。 Skill 檔案本質上是給 Claude 的指令。惡意的 Skill 可能包含 「把資料傳送到外部伺服器」或「刪除本地檔案」之類的步驟。 在引入任何第三方 Skill 前，務必先用 cat 或文字編輯器閱讀全文， 確認步驟合理、OpenCLI 指令符合預期。

5. 實戰：撰寫你的第一個 Skill

現在讓我們從零開始寫一個完整的 github-trending-digest.md Skill。 這個 Skill 會抓取 GitHub Trending 並產生每日技術摘要報告，是入門的絕佳範例： 流程清晰、有參數輸入、有錯誤處理、有明確的輸出格式。

github-trending-digest.md — 完整 Skill 檔案 
---
name: github-trending-digest
description: 抓取 GitHub Trending 並產生每日技術摘要報告
trigger: /github-digest
---

# GitHub Trending 每日摘要

## 前置需求
- 已安裝 GitHub adapter：`opencli adapter install github`
- 選擇性：已執行 `opencli github auth` 以提高 API 速率限制

## 參數
- `lang`（可選）：程式語言篩選，例如 `typescript`、`python`、`go`，預設為全語言
- `since`（可選）：時間範圍，可選 `daily`、`weekly`、`monthly`，預設 `daily`

## 步驟

1. 執行以下指令取得趨勢清單：
   `opencli github trending --lang "${lang}" --since "${since:-daily}" --limit 25 --format json`

2. 對清單中每個 repo 抓取基本資訊（star 數、語言、簡介）：
   `opencli github repo-info --repos-from-stdin --format json`

3. 分析結果，依以下維度歸類：
   - 新興框架與工具
   - AI／ML 相關專案
   - 開發者效率工具
   - 值得注意的新星（< 1 週內暴增 500+ stars）

4. 如果某個 repo 的 README 摘要不清楚，執行：
   `opencli github readme --repo "${owner}/${repo}" --max-length 500`
   取得更多描述，但每次執行最多查詢 5 個 repo，避免超出速率限制。

5. 如果步驟 1 或 2 回傳錯誤（exit code 非 0），
   立即停止並提示使用者：「GitHub adapter 連線失敗，請確認
   `opencli adapter status github` 後重試。」

## 輸出格式

產生完整 Markdown 報告，格式如下：

```markdown
# GitHub Trending 摘要 — YYYY-MM-DD

**語言篩選：** {lang 或「全語言」}
**時間範圍：** {since}

## 今日亮點（Top 5）
| 名次 | Repo | Stars | 語言 | 簡介 |
|------|------|-------|------|------|
| 1    | ...  | ...   | ...  | ...  |

## 分類速覽

### AI／ML 專案
- **repo-name**：簡短說明（本日新增 X stars）

### 開發工具
...

## 本週值得追蹤
列出 3-5 個本週成長最快的專案，附上一句話評論。

## 資料來源
- 抓取時間：{timestamp}
- 總計分析：{count} 個 repo
```

將報告儲存到 `github-trending-YYYY-MM-DD.md`，並在對話中顯示摘要版本。

這個 Skill 示範了幾個重要的設計模式：

  • 參數設計：使用 shell 預設值語法設定參數，讓參數可選。 Claude 在執行時會詢問或從上下文推斷參數值。
  • 速率限制保護：步驟 4 明確限制「最多查詢 5 個 repo」， 避免因過度呼叫 API 而被封鎖。
  • 錯誤處理：步驟 5 說明失敗時的處置方式， 讓 Claude 知道遇到錯誤不要默默繼續，而是回報給使用者。
  • 輸出格式：用 Markdown 範例明確定義報告結構， 確保每次執行的輸出格式一致，方便後續處理或比較。

從真實需求出發。寫 Skill 的最好時機是： 你剛剛手動完成一個重複性任務，並且覺得「下次如果能一鍵完成就好了」。 把你剛才做的步驟記錄下來，稍微整理成 Skill 格式，就是一個有用的 Skill。

6. 管理已安裝的 Skills

隨著 Skills 數量增加，你需要一套管理策略。以下是常用的管理指令和工作流程：

列出與搜尋 Skills 
# 列出全域 skills
ls ~/.claude/skills/

# 列出專案 skills
ls .claude/skills/

# 查看某個 skill 的詳細內容
cat ~/.claude/skills/github-digest.md

# 搜尋包含特定 adapter 的 skills（Linux/macOS）
grep -rl "opencli github" ~/.claude/skills/

Skills 的日常管理操作：

  • 更新 Skill：直接用文字編輯器修改 .md 檔案， 下次呼叫時立即生效，不需重啟 Claude Code。
  • 停用 Skill：從 CLAUDE.md 移除對應的 @import 那一行即可， Skill 檔案本身可以保留備用。
  • 重新命名：修改 frontmatter 的 trigger 欄位， 同時更新 CLAUDE.md 中的路徑引用與描述。
  • 除錯：如果 Skill 執行結果不如預期，先確認 opencli 指令本身是否正常， 再檢查步驟說明是否夠明確，必要時加入「若此步驟失敗，請輸出錯誤訊息並停止」的說明。
把 Skills 加入版本控制 
# 把專案 skills 加入 git 版本控制
git add .claude/skills/
git commit -m "feat: add github-trending-digest skill"

# 建立 .gitignore 排除含有敏感資訊的 skill（如含有 token）
echo ".claude/skills/private-*.md" >> .gitignore

# 全域 skills 不加入專案 git，改用獨立的備份 repo
cd ~/.claude/skills
git init
git remote add origin git@github.com:yourname/my-claude-skills.git
git push -u origin main

團隊共享建議： 把 .claude/skills/ 目錄加入專案的 git repo， 所有成員 clone 後就能立即使用相同的 Skills， 確保團隊工作流程的一致性。同時在 CLAUDE.md 中加入 Skills 的引入， 讓每個人打開專案就能直接使用，不需要額外設定。

7. Skills 的最佳實踐

設計良好的 Skill 具備以下特質：

單一職責原則

一個 Skill 只做一件事。不要把「抓取 GitHub Trending」和「發 Slack 通知」寫在同一個 Skill 裡， 拆成兩個 Skill 各司其職，需要時再組合使用。 這樣的好處是個別 Skill 容易測試、容易修改，出錯時也更容易定位問題。

明確的前置需求

在 Skill 開頭的「前置需求」段落，寫清楚需要哪些 adapter 已登入、 需要哪些環境變數、需要什麼權限。 好的前置需求說明讓 Skill 在任何機器上都能順利執行， 也讓接手的同事不用猜測環境設定。

實踐項目 不好的寫法 好的寫法
OpenCLI 指令 opencli github trending opencli github trending --limit 25 --format json
錯誤處理 （沒有提及） 「若指令失敗，提示用戶執行 adapter status 後重試」
輸出格式 「產生一份報告」 提供完整的 Markdown 模板，含表格欄位定義
參數設計 無參數，寫死所有值 關鍵值設為參數，提供合理預設值
速率限制 無限制呼叫 明確指定最大呼叫次數或加入延遲說明

加上 --limit 與 --format json

幾乎所有 OpenCLI 指令都支援 --limit 控制回傳筆數， 以及 --format json 輸出結構化資料。 在 Skill 步驟中固定加上這兩個參數，讓 Claude 能穩定地解析輸出、 避免因資料量過大造成處理超時。

錯誤處理說明

在關鍵步驟後加入錯誤處理說明，例如： 「如果此步驟回傳錯誤（exit code 非 0），立即停止並提示用戶執行 XXX。」 Claude 不會自動處理錯誤，需要 Skill 明確告知遇到問題時的行為—— 否則 Claude 可能會帶著錯誤結果繼續執行，產生無意義的輸出。

8. OpenCLI 官方 Skills 套件

OpenCLI 官方維護了一套精選 Skills，涵蓋最常見的自動化場景。 這些 Skills 經過測試、文件完善、定期更新，是快速上手的最佳起點。

官方 Skills 目錄結構 
# 官方 skills 分類結構
~/.claude/skills/official/
├── social/                    # 社群監控類
│   ├── twitter-monitor.md     # Twitter 趨勢監控
│   ├── reddit-digest.md       # Reddit 熱門摘要
│   └── hn-daily.md            # Hacker News 每日精選
│
├── devtools/                  # 開發者工具類
│   ├── github-digest.md       # GitHub Trending 摘要
│   ├── pr-review-helper.md    # PR 審查輔助
│   └── release-watcher.md     # 新版本釋出監控
│
└── content/                   # 內容聚合類
    ├── rss-reader.md          # RSS 訂閱摘要
    ├── newsletter-digest.md   # Newsletter 聚合
    └── arxiv-daily.md         # arXiv 論文每日精選

三大分類說明：

分類 代表 Skills 適用場景
社群監控類 twitter-monitor、reddit-digest、hn-daily 品牌監聽、競品追蹤、話題分析
開發者工具類 github-digest、pr-review-helper、release-watcher 技術動態追蹤、開源專案監控
內容聚合類 rss-reader、newsletter-digest、arxiv-daily 資訊整合、知識管理、研究追蹤
安裝官方 Skills 套件 
# 安裝 OpenCLI 官方 skills 套件（完整版）
git clone https://github.com/opencli/skills-official ~/.claude/skills/official

# 只安裝特定分類（社群監控）
mkdir -p ~/.claude/skills/official-social
curl -o ~/.claude/skills/official-social/twitter-monitor.md \
  https://raw.githubusercontent.com/opencli/skills-official/main/social/twitter-monitor.md
curl -o ~/.claude/skills/official-social/reddit-digest.md \
  https://raw.githubusercontent.com/opencli/skills-official/main/social/reddit-digest.md

# 更新至最新版本
cd ~/.claude/skills/official && git pull
CLAUDE.md — 引入官方 Skills 
# 在 CLAUDE.md 中引入官方 skills

## 社群監控
@~/.claude/skills/official/social/twitter-monitor.md
@~/.claude/skills/official/social/hn-daily.md

## 開發工具
@~/.claude/skills/official/devtools/github-digest.md
@~/.claude/skills/official/devtools/release-watcher.md

從官方 Skills 學習。 即使你有自訂需求，也建議先閱讀官方 Skills 的寫法。 官方 Skills 示範了成熟的步驟設計、錯誤處理模式， 以及如何與不同 adapter 的特性相配合—— 這些都是撰寫自己的 Skill 時很好的參考範本。

本章小結

本章涵蓋了 Skills 從概念到實戰的完整知識：

  • Skills 的本質是觸發條件 + 步驟說明 + OpenCLI 工具調用，讓重複性工作標準化、可共享
  • 檔案結構分為 YAML frontmatter（metadata）和 Markdown 正文（工作流程說明），撰寫門檻極低
  • 存放位置分全域（~/.claude/skills/）和專案（.claude/skills/），都需在 CLAUDE.md 引入才生效
  • 安裝社群 Skills要遵循「先看後用」的安全原則，確認內容後再引入
  • 撰寫 Skill的關鍵是單一職責、明確前置需求、加入 --limit 和 --format json、說明錯誤處理
  • 版本控制專案 Skills 讓團隊共享工作流程，全域 Skills 可用獨立 git repo 備份
  • 官方 Skills 套件提供三大分類的現成工作流程，也是學習 Skill 設計的優良範本
